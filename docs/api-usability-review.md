## Correctness first

| Input to Transcriber | Observed result | Proposed change |
| --- | --- | --- |
| A FLAC upload and a raw PCM model target | A `File` labeled `audio/flac` is rejected. Passing the same file's `ArrayBuffer` sends the **entire FLAC container**, starting with `fLaC`, as 24 kHz PCM. File transcription identifies the FLAC correctly, and `.loadsAudio` decodes it to the expected samples. | Distinguish identifiable **finite** encoded recordings from raw bytes consistently. Decode a supported recording or report that decoding is required before dispatch. Preserve already-compatible raw inputs and the single-consumer stream contract. |
| A WAV on a component with reusable headerless-PCM defaults | Without `sourceFormat`, the model gets the samples. With a complete matching PCM layout configured, it also gets the **RIFF header as sound**. With just rate and channels configured for typed arrays, the same WAV is rejected for missing encoding. | Use the validated WAV header for a self-describing recording. Apply the reusable raw layout to headerless inputs. Test alternating a WAV and raw samples on the same component. |
| A `File` explicitly labeled `audio/basic` with valid headerless μ-law data | Ordinary file transcription discards the supplied MIME type. The SDK cannot identify those bytes and labels them `audio/wav`. Its URL/download path preserves `audio/basic` for the same bytes. | Preserve usable source MIME information. The installed SDK accepts MIME on a download result and lacks an equivalent field for supplied transcription bytes. Prefer adding that support at the SDK boundary. A targeted error is preferable to knowingly sending an incorrect label. |

The first two cases share preparation code with Translator. A separate Chromium probe decoded complete FLAC and WebM/Opus uploads into real `AudioBuffer` objects using `OfflineAudioContext.decodeAudioData()`. That makes browser decoding a viable improvement for formats the browser supports. It would extend the current portable PCM/WAV contract. Headerless streams and containers requiring seeking or track selection have different requirements. [Supplied audio preparation](../src/audio/supplied.ts) · [Model dispatch](../src/audio/input.ts)

## Where composition still costs the caller work

| Workflow | Work the caller does today | Smallest useful change |
| --- | --- | --- |
| Generate an image, then edit it | `draw('Edit', first.images)` fails. `draw('Edit', first.images.map(image => image.uint8Array))` works. A browser picker `File` needs `arrayBuffer()`, and an HTTP(S) `URL` object needs `.href`. | Accept SDK generated files, browser `File`/`Blob` and HTTP(S) URL objects in the existing image and mask slots. Accepting these values would require no new public helper. [ImageGenerator](../src/factories/ImageGenerator.ts) |
| Feed generated speech or an upload to the next model | `transcribe(spoken.audio)` fails for a generated WAV. Extracting `.uint8Array` works. In LLMAgent and Decision file parts, callers also assemble bytes and MIME type that a picker file or generated file already carries. | Accept a selected file in the existing audio or attachment slot and preserve its metadata. The caller still selects the attachment, message role and text. Raw generated speech may carry its rate on the enclosing speech result. An encoded WAV already carries its own layout. [Audio inputs](../src/audio.ts) · [Speech result](../src/factories/SpeechGenerator.ts) |
| Stream microphone or file chunks | An async generator of PCM chunks fails at direct transcription. A Node `Readable` of byte chunks fails there too. The same generator passed through `toReadableStream()` delivers the original bytes. Translator has the same public requirement, and `.loadsAudio` requires a Web stream for incremental uploads. SpeechGenerator already accepts async iterables of text. | Bridge an async iterable inside the receiving component. Keep native Web streams on their existing identity path. Preserve backpressure, cancellation, one-shot ownership and deliberately replayable sources. [Audio stream input](../src/audio/input.ts) · [Existing bridge](../src/streams.ts) |
| Embed or rerank an immutable list | TypeScript rejects `embed(passages)` and `rerank(query, passages)` for `readonly string[]`. Both operations succeeded with a frozen list in JavaScript. Spreading it fixes only the type error. | Accept readonly lists at the Casai boundary. Adapt once where the SDK exposes a mutable array, including through its result. Preserve document type inference. [Embedder](../src/factories/Embedder.ts) · [Reranker](../src/factories/Reranker.ts) |

Two further choices affect APIs beyond media.

- A tool with no public arguments still needs `inputSchema: z.object({})`. A constant-returning `Function.asTool` fails construction without it. The SDK requires a schema on its descriptor, which Casai constructs. Casai could supply a closed empty schema when omission explicitly means zero public arguments. Author-declared inputs, transforms and authorization remain deliberate. Inferring public fields from a closure or configured resource would change what a model can control. [Tool construction](../src/factories/component-factory.ts) · [Tool descriptor](../src/runtime/execution.ts)
- The interchangeable-classifier example needs a function solely to return `(await modelClassifier(ticket)).output`. This is an opportunity for an opt-in value-returning callable if the pattern recurs. Automatic unwrapping would lose access to history, tool calls and generated files. The ordinary full SDK result and the existing tool completion rules have distinct consumers. [Classifier example](matrix/articles/change-implementation-keep-workflow.md) · [Result handling](../src/runtime/augment-result.ts)

## Information the component still needs

A source header tells Casai what it has. It cannot say which format a particular model accepts, which language to translate into, or which audio track the application wants when native best-track selection is unsuitable. The installed transcription and translation model interfaces expose no list of accepted input formats. Configure the model target once on the reusable component. A source description is necessary only for the raw layout that the caller has separated from its metadata.

The translation SDK emits output audio chunks without a format field. Copying the requested format onto the result as the actual format could corrupt the next handoff. The installed OpenAI adapter, for example, warns when `outputAudioFormat` is supplied and produces its fixed PCM format. Likewise, a tool's JSON string alone cannot establish whether the application authorizes downloading it. The guide's URL tool makes that decision in the schema once and leaves fetching to the SDK. [Translation collection](../src/factories/Translator.ts) · [Transcription examples](matrix/documentation.md#guide-transcriber)

## Which helpers still earn a public place?

| Public helper or group | Why a caller uses it |
| --- | --- |
| PCM/WAV conversion, resampling, chunk concatenation and FFmpeg preparation | All are private. Supported component inputs need no public audio conversion helper. |
| `toReadableStream` | Currently required for an async-iterable audio source. Casai can own that bridge. It remains independently useful when an external Web API requires a `ReadableStream`. |
| `collectStream`, `collectTextStream` | Optional ways to consume a live iterable into an array or string. The consumer chooses whether to buffer. Ordinary completed components and tools with a declared stream result already collect where appropriate. |
| `textStreamSchema`, `streamSchema` | Declare how to validate a stream and how to present a tool result. The same sequence of strings can mean one text or an array of independent strings. Even reading the first chunk cannot resolve that choice. |
| `makeSharedIterable` | The owner explicitly requests replay, retention and disposal. Automatically retaining a live microphone or an unbounded stream would change its lifetime. |
| `raceLoaders`, `raceParent`, `overrideParent`, and loader classes | Select where executable sources may come from and which loader wins. Ordinary child-first inheritance already works without a directive. |
| `denyPendingApprovals` | Records the application's decision to deny pending actions when changing turns. Approval intent cannot be inferred from a new prompt. |
| `bindToolContext` on a tool | For direct native SDK integrations that provide public input defaults through context, it keeps the advertised descriptor matched to the same bound context. Casai tool registries already do this internally. |
| `ModelMessageSchema`, `PromptStringOrMessagesSchema`, `z` | Reusable validators for application-owned boundaries. Casai already validates its prompt inputs. Callers need no separate validation step to use a component. |

## Scope and verification

The inventory covered all 12 implemented factories. Config, Template, Script and Function were checked for source selection, settings inheritance, validation and tool projection. LLMAgent and VoiceAgentBackend were checked for history, approvals, native entry points and tool binding. Decision, Embedder, Reranker, ImageGenerator, Transcriber, SpeechGenerator and Translator were checked against their SDK request and result types. VoiceAgentClient and VideoGenerator are planned components. [Public exports](../src/index.ts) · [Component matrix](matrix/README.md)

The runtime probes used SDK test models and inspected their actual requests. They ran against source and build output, with real FFmpeg for the FLAC control. TypeScript 7 checked each rejected call alongside a working alternative against both source and emitted declarations, with exact optional properties on and off. Chromium checked the browser codec opportunity separately. These probes establish what crosses the SDK boundary, independently of any individual provider's media support.

Guide corrections from this review use a plain image tool with configured style references, let the SDK download a model-supplied URL, pass a request body directly to native preparation, and use the document already present in every ranking entry. They also clarify direct WAV handling. [User guide](matrix/documentation.md)
