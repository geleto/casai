# Cancellation and Timeouts

Status: the invocation contract below is agreed for the planned API. Cascada interruption, cleanup, and automatic propagation still need upstream design and implementation. Other deferred features are in [future.md](future.md).

## Agreed Invocation Contract

- **Every callable has `.run()`.** LLMAgent, specialized operations, Template, Script, and Function accept named inputs plus `abortSignal` and `timeout`. For example, `workflow.run({ context: { document }, abortSignal: request.signal, timeout: 10_000 })`. For Script/Template workflows this does not yet cancel nested model calls; those calls can continue making requests and consuming tokens, and engine interruption itself needs upstream support. Do not mutate shared configuration or require a derived component for each request.
- **SDK cancellation stays native.** LLMAgent forwards invocation cancellation to the SDK, which passes its signal to tools. A component used as a tool forwards that signal to its execution. New core/agent constructor configuration rejects `abortSignal` until configured-signal combination is implemented; pass it per call. Configured timeout is allowed, with a defined call timeout replacing it.
- **Total timeout includes asynchronous preparation.** Establish one absolute end time and cancellation signal before asynchronous schema processing, loaders, prompt functions, request hooks, or other preparation. Numeric timeouts and `timeout.totalMs` cover preparation plus execution. The SDK reuses that signal rather than starting another total timer; omit the already-owned total limit only at backend dispatch and retain SDK step/chunk/tool limits. Preserve caller/configuration timeout objects. If preparation expires, reject without dispatch or accepting late results. Keep the scope alive through underlying streaming execution, and clean up owned timers/listeners on completion, failure, or closure. An object without a total limit creates no total deadline.
- **Function callbacks and function preparers receive execution options.** Their second argument includes the invocation signal, which application work such as `fetch` or opening audio can use. Forward it during preparation and check cancellation before starting the backend. This cooperative JavaScript path does not require automatic Cascada propagation.
- **Cascada owns return and native stream failure.** Complete returns are healthy values or the engine's poison/failure outcome. Native `stream`/`tstream` delivers a valid prefix and terminates at its first error. Casai reuses native validation and failure rather than scanning poison, repairing partial objects, or providing different views for Script and JavaScript consumers.
- **Streams retain ordinary consumption.** Passing a stream to a component permits it to consume that source. Returning it does not restore consumed items. Casai's lazy validation wrapper is one reader of the source and forwards schema-produced elements to its caller without replay or another consumption pass. Runtime-provided sharing remains a separate capability.
- **Source failure is terminal.** An iterator throw, abort/timeout, or fatal producer error cannot be resumed after the producer closes. Follow the runtime's native failure rules. Recoverable SDK tool errors and provider retries do not automatically fail an entire LLMAgent execution.
- **SDK views retain their contracts.** SDK event streams represent terminal failures as events where applicable; text/element projections can omit those events. StreamingTranscriber retains its own SDK event protocol. Casai's LLMAgent `value` reports terminal SDK failure through iteration. This SDK adaptation is separate from Cascada's native stream behavior.
- **Streaming tools collect one execution.** Finite native streams become completed tool results. LLMAgent tools apply the same final-output availability and failure rules as `value`. A StreamingTranscriber tool requires a script/function preparer that opens bounded audio; it waits for normal completion and returns the final transcript. Failures reject collection; stopping an indefinite session is not silently treated as success.
- **History distinguishes failure from a legitimate pause.** A terminal execution failure or abort rejects Casai `messageHistory`; keep the prior conversation. Pauses for tool approval or external results retain resumable history and completed steps even when `value` has no final output. Output unavailability alone is not whole-execution failure. Preserve SDK fields and their own completion/error behavior.

LLMAgent `value` selects only final application output. Buffer candidate output while loop finality is unknown, without delaying SDK `stream` events; keep `steps` as completed records or their promise. No additional activity accessor is added. Cancellation must interrupt selection while it is waiting or buffering, and must never release buffered partial output as a successful answer. See [the result contract](agents-design.md#output-and-result-contract).

## Implementation Order

Build and test the shared invocation deadline scope early in Phase 1. Its fixtures use that primitive for preparation, Phase 1b reuses it before asynchronous schema work, and Phase 2 integrates it into public call settings. Phase 1b need not wait for the remaining SDK probes; do not build a separate temporary deadline adapter. A single end time/signal covers preparation and backend execution: three seconds of preparation under a ten-second total leave seven seconds before that same signal aborts, without a new backend timer or repeated remaining-budget calculations. If a parent deadline is explicitly known, retain the earlier end time and reuse the parent signal unless the child adds an earlier deadline. Automatic propagation is separate upstream work. Test early expiry, signal reuse, non-total SDK limits, cleanup, and stream lifetime. See [the timeout contract](agents-design.md#cancellation-timeouts-and-usage).

Phase 1 owns the reusable internal deadline scope, and its fixtures forward cancellation and probe preparation deadlines. Phase 1b integrates that same scope before asynchronous input parsing, without adding a public `.run()` API. Phase 2a integrates execution options, cooperative Function cancellation, SDK-to-component tool signals, and lazy stream-wrapper closure forwarding. Phase 2b applies that same scope and the final tool adapters to LLMAgent, including finite streaming tools. Phases 1-3 do not wait for new Cascada interruption or propagation. Phase 4 forwards native rendering, validation/failure, and cleanup APIs; the engine owns buffers, readers, scheduling, and shared-source lifetime. Accepting `abortSignal` or `timeout` cannot force-stop unsupported engine operations or arbitrary JavaScript.

## Upstream Work

1. **Cascada root cancellation.** Connect Phase 2a's per-call execution options to engine interruption and cleanup once supported. A server supplies `request.signal` to the outermost `.run()`. Keep execution state separate from user data; the Casai call shape and JavaScript/SDK forwarding do not depend on this engine work.
2. **Limits on every component.** Support configured `abortSignal` and `timeout` as well as per-call settings. Combine independent cancellation sources, choose the earlier parent/child absolute end time, and reuse an existing parent deadline signal unless the child introduces an earlier limit. LLMAgent retains the SDK timeout form, including supported per-step/chunk/tool limits. Config inheritance remains useful for reusable limits, but is not the request invocation API.
3. **Poison on cancellation.** Cascada represents aborted/timed-out computations according to its native error contract, preserving causes. Complete returns are healthy or poison/failure; native streams terminate at the first error after any valid prefix. Casai forwards execution options and native outcomes, without special consumer handling.
4. **Automatic nested propagation.** A context channel carries signal, deadline, and call-tree identity into Script/Template calls. Async context tracking carries them through Function callbacks and other JavaScript. External work still needs the signal where its API requires it.
5. **Scheduling and cleanup.** Cascada and the SDK stop scheduling cancelled work and clean up their owned producers. Casai passes signals and forwards early closure through its adapters according to the source's contract. A shared cursor closing or a render ending does not by itself dispose a shared source; its owner controls disposal. Returned live streams must survive the component call's completion. Do not cancel unrelated branches or other consumers because one exported view fails. Iterator `return()` alone does not interrupt an `await` already in progress.
6. **Telemetry.** Retain usage and timing from work performed before failure or cancellation.

## Limits

JavaScript cannot force-stop work that ignores a signal. Such work may finish in the background; discard its result when the owning call has ended. A public cancellation setting must not be documented as complete nested cancellation until runtime support exists.
