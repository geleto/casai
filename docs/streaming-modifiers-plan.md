# Phase 6: Streaming modifiers and audio preparation — implementation plan

Date: 2026-11-07; reviewed 2026-11-13. Status: selected API direction; the type prototype and implementation are still pending. Ordinary audio components provide completed results through the selected request shape and support their completed tool forms, including Translator. Streaming-only speech requires an object output format or non-string text; `.loadsAudio` requires the native binding and installation. Combined streaming/tool modes remain prohibited. Optional native loading and necessary header inspection are resolved in the [plan review](streaming-modifiers-review.md#completed-delivery-and-tools-2026-11-13).

This is the detailed plan for [Phase 6: Streaming modifiers and audio preparation](plan.md#phase-6-streaming-modifiers-and-audio-preparation). Deliverables A and B are internal stages; both must satisfy their completion criteria before the phase is complete.

Implement the shared modifier, Config/inheritance, runtime-control and type changes; replace the separate streaming audio component names with `.asStream` variants; add completed execution/tool support including ordinary Translator; and provide recording preparation. The [Phase 6 scope index](plan.md#implementation-scope-and-contract-links) links all required work and decision records. Reuse native SDK execution and completion semantics. Deliver the factory/input/result changes first and the independent audio preparation utility second; neither requires a general audio runtime.

Preserve the existing configuration type rule across all components and standalone/inherited Config fragments: the effective settings must fit one applicable component/operation shape, with no unrelated fields. The new complete and streaming audio contracts must remain separate alternatives. The review exposed runtime gaps in Casai-owned streaming controls; it did not establish that mixed configuration shapes are accepted by TypeScript.

**Native backend decision (2026-11-13, latest):** retain node-av and use its stock build for development now. Every Casai beta/final release requires a verified LGPL node-av build as the documented default and native integration baseline. Prefer an upstream LGPL variant; if unavailable in time, use a minimal node-av build/packaging fork. The [development and release policy](#native-backend-selection) supersedes the earlier requirement to select/prototype an alternative before implementing B. Preserve the explicit GPL choice, optional entry and media API.

## Target API

| Current API | Replacement | SDK operation retained |
| --- | --- | --- |
| `StreamingSpeechGenerator(...)` | `SpeechGenerator.asStream(...)` | `experimental_streamSpeech` |
| `StreamingTranscriber(...)` | `Transcriber.asStream(...)` | `experimental_streamTranscribe` |
| `StreamingTranslator(...)` | `Translator.asStream(...)` | `experimental_streamTranslate` |
| New complete-result convenience | `Translator(...)` | Reuse `experimental_streamTranslate` once with finite input and collect its result |
| New media-source convenience (B) | `Transcriber.loadsAudio(...)`, `Translator.loadsAudio(...)` | Prepare a file/URL's selected audio for the same complete or streaming native operation |

**Confirmed 2026-11-13:** ordinary `SpeechGenerator(...)`, `Transcriber(...)` and `Translator(...)` return completed results. They handle a model that requires native streaming internally, collecting that execution without requiring an application-authored Function wrapper. `.asStream` selects incremental result delivery; it does not force callers to expose a live result merely because the provider uses streaming. All three ordinary families support `.asTool`, including `Translator.asTool` and compatible source-prepared forms. This supersedes the earlier native-complete-only restriction on ordinary speech/transcription and the omission of completed Translator tools.

This Translator is specifically a **speech-to-speech** component. The installed SDK exposes only `experimental_streamTranslate`, but streaming input need not come from a microphone: a recording can supply a finite stream. The ordinary component provides completion/collection convenience over that operation. Ordinary text translation uses a non-streaming LLMAgent.

For ordinary text translation, use instructions such as: "Translate the supplied text into French. Preserve its meaning, tone and formatting. Return only the translation." Supply the source text as the agent's prompt. No separate text-translation component is needed.

```typescript
const translate = Translator.asStream({
  model,
  inputAudioFormat,
  targetLanguage: 'fr',
});
const result = await translate(audioStream);
```

Here the application supplies a native translation model, audio format and fresh raw-audio stream. The call returns the native live result. Named invocation is also supported through `translate.run({ audio: audioStream })` as an alternative to the last line, using the stream once.

The ordinary form uses `Translator({ model, inputAudioFormat, targetLanguage: 'fr' })` and waits for the finite recording's completed result. Both Translator modes and every transcription path using native streaming accept reusable finite raw audio bytes (`Uint8Array`, including Buffer, and `ArrayBuffer`) as well as native audio streams. `.asStream` changes result delivery, not finite-byte admission. Complete delivery requires a source that ends; it does not need a distinct byte-input adapter. Encoded-file versus raw-audio format requirements still belong to the selected native operation and explicit preparation.

Expose the same API through named imports and `create`. Remove the three old public `Streaming...` exports and their public component-kind names; keep no compatibility aliases for these unreleased names. Native SDK names and experimental status stay unchanged.

Source modifiers come first, followed by either `.asStream` or `.asTool` where supported. **Confirmed 2026-11-13:** no component combines `.asStream` and `.asTool`, including through direct flags, parents or Config fragments. This removes the previously selected prepared-streaming-transcription exception; it also applies to future Template streaming. Script/Function schema-declared stream collection and native third-party SDK tools are separate contracts and remain unchanged.

```typescript
SpeechGenerator.asStream({ model });
SpeechGenerator.withTemplate.asStream({ model, text: 'Hello {{ name }}.' });
Transcriber.withFunction.asStream({ model, audio: openAudio, inputAudioFormat });
Translator.withFunction.asStream({ model, audio: openAudio, inputAudioFormat, targetLanguage: 'fr' });
Translator.withFunction.asTool({ model, audio: openRecording, inputSchema: recordingSchema, inputAudioFormat, targetLanguage: 'fr' });
```

These illustrate the planned factory paths; dependencies are application-supplied. Do not add reverse modifier orders such as `.asTool.asStream` or `.asStream.withFunction`.

| Family | Streaming source modifiers | Streaming tool support |
| --- | --- | --- |
| SpeechGenerator | Default, `withText`, `withTemplate`, `withScript`, `withFunction`, `loadsText`, `loadsTemplate`, `loadsScript` | None |
| Transcriber | Default, `withScript`, `withFunction`, `loadsScript`, `loadsAudio` (B) | None |
| Translator | Default, `withScript`, `withFunction`, `loadsScript`, `loadsAudio` (B) | None |

Translator follows the same factory structure as the other audio families: its base and source selectors construct complete-result components, and `.asStream` selects incremental results. No non-callable namespace exception is needed. Both forms have ordinary calls, `.run()` and `.config`; raw streaming input retains native format requirements.

The source table includes the full phase scope. A migrates the existing source modes; B adds `.loadsAudio` under the [modifier contract](#audio-resource-modifier) and [native media-input contract](#file-and-url-media-inputs). The factory paths and numeric `track` selection are selected plan contracts; implementation, the remaining helper/backend setup signatures and their type proof are pending.

LLMAgent's existing streaming behavior and prohibition on streaming tools remain unchanged. Template streaming remains future Phase 7 work. Script and Function retain their existing schema-declared stream contracts.

An ordinary non-tool LLMAgent retains both native Agent methods, `.generate()` and `.stream()`, regardless of its default. Its `streaming` setting selects ordinary calls, `.run()` and `resume()`. Do not split LLMAgent's shared configuration or remove either native method as a side effect of separating the audio operation contracts.

### Audio resource modifier

**2026-11-13 plan consolidation:** use `.loadsAudio`, following `.loadsText`, `.loadsTemplate` and `.loadsScript`. It describes how a component obtains its input; it is not a method that performs a separate load before invocation. Do not add `.loadAudio` or `.load` aliases. Support these paths on both `Transcriber` and `Translator`, through named exports and `create`:

```typescript
Transcriber.loadsAudio(transcriberConfig);
Transcriber.loadsAudio.asStream(transcriberConfig);
Transcriber.loadsAudio.asTool(mediaToolConfig);
Translator.loadsAudio(translationMediaConfig);
Translator.loadsAudio.asStream(translationMediaConfig);
Translator.loadsAudio.asTool(translationMediaToolConfig);
```

These are planned factory-path illustrations with application-supplied configuration, not executable current-API examples. SpeechGenerator has no audio input and gains no `.loadsAudio`. Config exposes the same selector and compatible source-first chains as an incomplete reusable fragment; completion must select a compatible audio owner. No `.asStream`/`.asTool` combination is allowed. Preserve one selected source mode, structural symbol metadata, ordinary Config merge/override laws and safe source-mode unions; this is not a chain of multiple source preparers.

In this mode the existing `audio` source field accepts a file path or media URL (`string` or `URL`). A source string explicitly means a resource reference, never base64 or executable text. Ordinary audio mode retains its native data meanings; bytes/streams and script/function-produced inputs remain available through their existing paths. Configure a reusable resource or supply/replace it on each ordinary call; named calls use `.run({ audio: resource, ...settings })`. Source shorthand remains primary, including path/URL unions and inherited defaults. Each invocation opens a fresh resource; constructing a component does not open it or cache decoded media. `.loadsAudio` needs no Cascada `loader` setting and must not reuse the generic named-script/text requirement for one.

Use `mediaSettings.track?: number` in configuration and named invocation settings, with no additional positional slot or top-level `track` alias. Omission chooses the native best audio stream; a supplied non-negative integer selects that zero-based container stream index. Invalid, missing, non-audio or undecodable explicit selections fail. Retain ordinary configuration clearing and call-time undefined-as-omission rules; no new sentinel is needed. Strip preparation controls from SDK model requests, preserving same-named application/context data as data. Native input options and credentials remain trusted preparation settings, supplied through configuration or trusted named invocation; the required native backend binding stays configuration-owned. An explicit preparer may map validated application choices to preparation settings. Follow the [media settings contract](#media-input-settings) and [media authentication/access boundary](#authentication-and-media-access), including fresh per-call credentials and separate model headers.

Completed `.loadsAudio.asTool` components use the declared parsed `audio` field as the resource input, with normal configured public defaults and private-source protection. They may resolve a caller-supplied resource without a preconfigured `audio` value; do not copy the rule requiring configured executable source on script/function tools. Reuse closed public input schemas, existing binding/injected execution, cancellation and completed result projections. Model arguments are not a settings envelope: `track`, transport options and backend setup do not become model-controlled simply by sharing a schema field name. Custom public input names or dynamically selected preparation settings use explicit preparers. Finite input/native completion remains required for completed results.

Loading reuses the same preparation/conversion path as the standalone helpers and preserves the selected native operation's input shape. Raw streaming requests require a resolved target `inputAudioFormat` under the [target-selection policy](#audio-target-selection); when native information cannot determine it, require an explicit target. Source headers describe the recording and do not establish model requirements. A file-transcription operation instead receives one finite encoded recording containing the selected audio. The prototype must define that encoding/sample policy and its provider limits explicitly; the current PCM/WAV writer baseline alone does not define it. Do not send raw PCM to a file operation, silently assume all providers accept the original container, or use translation's 24 kHz requirement as a global conversion default.

**Confirmed API review simplification (2026-11-13):** `.loadsAudio` always uses one media-preparation path. Remove the proposed SDK/provider-file passthrough optimization and its equivalence/track probing branches. Resolve the native request, target and effective media settings before opening, then acquire and select audio once through the preparation owner. Matching bytes may pass through inside that owner; this is not a second downloader or a second source open. Native seek/range/playlist requests within the same owner remain supported. Ordinary `Transcriber` keeps its native encoded bytes/URL behavior and provider selection. `.loadsAudio` requires node-av even for WAV or already-compatible media; native absence fails before source opening, with no local file/fetch or SDK downloader fallback. Main-entry helpers and supported absent-package conversion of supplied bytes/streams remain separate.

The SDK `download` hook belongs to ordinary encoded-input transcription and is not an FFmpeg access hook. Exclude it from `.loadsAudio` configuration and trusted named-call alternatives, and reject an effective defined hook before resource I/O; inherited settings must not be silently ignored. Preserve source-union and incomplete Config checking. Applications needing custom access supply authorized bytes/a fresh stream through an explicit preparer and the shared helper. Do not compose two source selectors or add an authentication router. Undefined follows existing configuration clearing and invocation omission rules.

Keep stream and FFmpeg adaptation internal. Require the isolated `casai/node-av` preparation binding in finished `.loadsAudio` components, directly or through Config inheritance; a missing binding is a construction/type error. This requirement does not make node-av mandatory for other Casai components or main-entry PCM/WAV helpers. Finalize the binding's exact setup signature in the B prototype without a main-entry import/re-export edge, global registration or application stream bridges. Ordinary Transcriber keeps SDK file/URL handling outside `.loadsAudio`.

### Audio shorthand

Secondary positional slots belong to the audio operation, independently of `.asStream`. Ordinary/raw Transcriber accepts `(audio, inputAudioFormat)`; encoded-file transcription uses `(audio)` without a format. Both Translator delivery modes accept `(audio, inputAudioFormat, targetLanguage)`. Speech retains `(text, voice?)`. In `.loadsAudio`, replace the audio slot with the file/URL resource; a supplied `inputAudioFormat` is the model target, never the source demuxer. Omit configured slots only under the existing unambiguous-role rules. Preserve prepared context ordering and explicit placeholders where context and format are both objects; do not guess from field names. Source demuxer, track, credentials and backend binding gain no positional slots. Tools resolve execution format/language in trusted configuration; their model arguments remain declared input/preparation data.

## Behavior to preserve

- Ordinary calls and `.run()` on a streaming component resolve to its native live SDK result. They do not collect the output before returning.
- Complete transcription retains its existing tool projection regardless of the native execution path. Remove the old public streaming tool adapter with the old factory, but reuse its native-final-value collection inside ordinary transcription where appropriate. No application wrapper or replacement collection modifier is required.
- Native complete speech and native streaming speech have different input/format contracts. Preserve those precise alternatives when collecting native streaming for ordinary delivery; do not treat the public delivery flag as a complete description of the internal SDK request.
- Native file transcription accepts an encoded recording; native streaming transcription accepts raw streams or finite raw bytes with a required format. Both can back completed delivery. The modifier does not decode containers, convert formats or open a microphone.
- Recommend ordinary Transcriber for whole prerecorded files, using the provider's file operation. Streaming byte admission remains supported, but inherits native session completion. The installed OpenAI adapter disables turn detection, commits once after input EOF and finishes on the first transcription-completed event. Verify finite-recording behavior with the provider; this source observation does not prove that it actually splits one committed recording. Add no Casai multi-item collector or extra commits to compensate for a hypothetical SDK limitation.
- Retain positional calls, context/source separation, required configuration, preparer inference, private bindings, parsed schema values, cancellation and native callbacks.
- Retain the shared live-input identity guard immediately before SDK dispatch. Preserve fresh-stream requirements, configured single-use streams, reusable configured bytes, and native ownership/cleanup rules. Do not buffer, replay or acquire probing readers to inspect/claim inputs, and add no second claim registry. Explicit conversion and completed-result collection consume their streams as described below.
- Provider support, SDK errors and completion semantics remain native. Selecting `.asStream` does not make an unsupported model stream. Selecting ordinary delivery permits supported native streaming plus completion; raw transcription and translation use their selected streaming request, while ordinary speech requires an object format or non-string text to select streaming execution on a streaming-only model.

## Completed delivery over native streaming

**Confirmed request-shape selection (2026-11-13, latest):** `.asStream` requires native incremental execution and reports the native error if the selected model does not support it. Ordinary calls and `.asTool` return completed results, using the native operation selected by the resolved request shape. There is no capability-driven fallback or automatic switch after failure. This supersedes the earlier promise of format-free transparent selection for every streaming-only speech model and closes the capability-discovery policy gate.

| Family and resolved request | Native operation for ordinary delivery | With `.asStream` |
| --- | --- | --- |
| Transcriber without `inputAudioFormat` | Complete encoded-file transcription | Raw input and its format are required; `.loadsAudio` can prepare them |
| Transcriber with `inputAudioFormat` | Streaming transcription, awaiting native final fields | Native streaming transcription |
| SpeechGenerator with string text and absent/string `outputFormat` | Complete speech generation | Native streaming requires its object-format alternative or omission; a string format is incompatible |
| SpeechGenerator with object `outputFormat` or native non-string text input | Streaming speech, collected once | Native streaming speech |
| Translator | Native streaming translation, collected once | Native streaming translation |

For ordinary speech, a streaming-only model needs an object-valued supported output format or a native non-string text input. A string-text call with omitted format deliberately selects complete execution and may fail on such a model. Native streaming speech itself permits omitted format; the explicit object on the ambiguous ordinary call is Casai's selection rule. Preserve native setting alternatives: non-string text plus a complete-only string format remains incompatible, not a conversion instruction. No new transport flag or model capability annotation is introduced.

Keep public delivery fixed at construction while selecting the native operation from the invocation's resolved source and settings, including inherited defaults and admitted named overrides. The selected SDK function owns model resolution, support checks, retries and errors, including string/global-provider models and supported version adapters. Model replacement never changes the selection rule. For `.loadsAudio`, resolve target settings and the corresponding native request before resource acquisition; its source is prepared into that request, not handed unchanged to a raw-audio operation.

The installed SDK does not provide a universal positive capability flag. Required `doGenerate` or present `doStream` members and `UnsupportedFunctionalityError` alone do not establish support or a safe retry boundary. Do not build a capability catalog, inspect model-ID patterns, issue trial generations, redispatch after rejection, or maintain a parallel model resolver. Request-shape selection removes that inference requirement rather than deferring it to another prototype.

Resolve/parse application inputs and render the source once. Adapt the admitted input to the selected native request, claim a stream once immediately before its actual handoff, and perform one model execution. Required raw audio formats remain explicit; arbitrary encoded bytes do not become PCM by dropping `.asStream`. Native file support stays available. Reuse the recording helpers for conversions that need them, without making native-code installation a requirement for already-prepared PCM.

Keep result adaptation local to each family. Transcription can await the SDK's authoritative final text, segments, language, duration, warnings, responses and provider metadata; do not rebuild final text from deltas. Speech must collect one native output stream and use actual emitted audio-format metadata to produce its completed audio representation and existing tool projection, preserving final native fields. Never label raw PCM as a WAV container or guess the actual format from a requested option. Reuse supported public byte/file helpers where available and verify the completed result's ordinary getters and tool serialization. Native complete results remain unchanged; document the locally completed stream path without claiming it is an untouched native complete-result instance.

The prototype must implement this dispatch table and verify native request shapes, finite input, result ownership, cancellation and nonfatal/fatal error distinctions. These are implementation checks of the selected contract; the native-operation selection policy is no longer open. Keep each family's adapters small and retain the one-shape rule.

A raw stream without its required format is invalid, not an encoded-file request. Raw transcription plus a resolved `inputAudioFormat` must never enter encoded-file transcription, which can default unidentified bytes to `audio/wav`. Conversely, encoded files require preparation before a raw streaming request. Source headers do not choose a remote model target. Speech string/object format alternatives likewise remain separate; never discard a string format to force streaming. The ordinary result type follows the admitted request alternatives, preserving native complete results and the local collected-stream additions.

An unsupported selected operation reports its native error; it does not trigger another operation. Preserve SDK retries within that operation. The earlier probe showing a download before unsupported complete transcription remains evidence against class-only fallback, not an outstanding requirement to discover a dispatcher. Tests must count source preparation, downloads, input claims and dispatch independently, including pre-handoff cleanup for Casai-owned resources.

Completed streamed speech must claim `fullStream` before any final-promise getter, retain emitted `audioFormat` (including `rate`) alongside the completed audio and in its JSON-safe tool projection, and retain native stream usage. `GeneratedAudioFile`'s media type/format alone cannot preserve PCM sample rate. Use the format of nonempty audio chunks; metadata-only empty chunks do not change it. If nonempty chunks change type/rate, the local single-file adapter must fail explicitly instead of concatenating incompatible audio, guessing one format or adding transcoding. Native `.asStream` still exposes those chunks unchanged. Preserve native complete results/projections, and finalize the additive collected-path declarations in the prototype. Do not claim per-chunk IDs/metadata survive collection; retain native final metadata, with event-level details available through `.asStream`.

Completion has two native boundaries. Transcription can use its authoritative final promises without a second reader or an added EOF gate. Speech/translation must drain the owned output stream to collect audio; a later stream failure rejects that collection even if native final promises already resolved. Native nonfatal error parts remain nonfatal. Test finish-then-error and cancellation-after-finish explicitly; document this necessary difference instead of adding a uniform stream-completion framework.

## Recorded-audio translation

Treat support for prerecorded audio as a required use case, not a consequence of whether the SDK supplies a function named `translate`. The ordinary Translator's purpose is to accept a finite recording and return its completed translated audio, native source/translated text and metadata. Prefer one native speech-translation execution over an automatic Transcriber/LLMAgent/SpeechGenerator pipeline, which would require additional models and change the operation's behavior.

Implement and verify the following selected adapter contract; the prototype checks its types and integration rather than reopening byte admission or completed-audio representation:

- Separate the recording's encoding from result delivery. The native translation operation accepts raw audio chunks plus `inputAudioFormat`. The OpenAI translation endpoint requires 24 kHz mono signed 16-bit little-endian PCM; an MP3/WAV container is not raw PCM. Define finite recorded-data admission and use the explicit preparation contract below. Do not guess that arbitrary bytes are PCM or add an implicit codec dependency.
- Use one shared raw-audio input normalization for ordinary/incremental Translator and every transcription path using native streaming. Wrap finite bytes in a fresh stream per invocation; preserve native streams as supplied. Configured, inherited, shorthand, named, preparer-returned and tool-prepared bytes use the same rule. Preserve schema/preparation/cancellation ordering and claim the actual stream once immediately before dispatch. Keep input bytes unmodified; borrowed views require callers to leave them unchanged during the run. Do not introduce a second component or competing input wrapper inside the conversion utility.
- Pull finite bytes in chunks of at most 9,600 bytes, returning the final remainder unchanged. This fixed bound aligns mono/stereo 8/16/24/32-bit PCM frames and is 200 ms at OpenAI's 24 kHz mono PCM16 format. It needs no format-dependent branch and does not promise alignment for every possible provider format. Preserve every input byte without padding or truncation. Native caller streams retain SDK handling; do not add a universal rechunker or pacing layer. The review's recalled 15 MiB append cap was not established for translation; do not encode it as a contract.
- Raw-byte admission never detects MP3/WAV or derives format from byte contents. Complete Transcriber bytes can be encoded files; streaming Transcriber bytes must match the declared native input format. Types cannot distinguish those byte contents. Document this at mode inheritance and test settings compatibility without introducing byte branding or content sniffing.
- Own `fullStream` before reading any final result promise. The SDK allows only one consumer; reading a promise first drains the stream internally and prevents audio collection. Consume one stream once, retain the needed audio parts, and read the native final text/metadata from that same execution. Do not reassemble authoritative text from partial events or rerun translation to obtain another result view.
- Share the native dispatch below the existing preparation boundary. Do not implement the complete form by constructing and invoking another Casai component after preparation; that would risk duplicate schema parsing, source preparation or input claims.
- Return completed `audio` as a `Uint8Array`: decode base64 audio parts with the public SDK byte utility and concatenate all audio bytes in stream order. Include the resolved native `sourceText`, `translationText`, `durationInSeconds`, `usage`, `warnings`, `response` and `providerMetadata`. A native text-only success has empty audio bytes. Do not invent a file type or infer the actual format from the requested `outputAudioFormat`: the generic result does not declare it, and OpenAI returns 24 kHz mono PCM16 while warning that requested output formats are unsupported. Callers who know the actual PCM format can explicitly build a WAV with the helper below. Plain bytes and that helper are selected; only their implementation/type verification remains.
- Follow the SDK's result-promise policy exactly for error parts: a non-fatal in-band error does not become a thrown Casai error or a collected `errors` field. The completed adapter collects audio and reads authoritative native final values; event-level observation uses the streaming component's returned `fullStream`. Preserve native failures for missing finish, insufficient output, transport errors and cancellation. Translation currently accepts any emitted audio part or nonempty final translated text at finish; do not replace this with Casai's idea of valid audio.

Completed output necessarily retains produced audio. This convenience is justified by the finite recorded-audio use case; it does not authorize buffering or replay in `.asStream`, a new transport, or a general stream-completion framework. `Translator.asTool` reuses this same completed execution and the existing tool assembly; streaming Translator remains unavailable as a tool.

#### File and URL media inputs

**2026-11-13 simplification:** the user clarified that the new loading requirement is media only. Delegate media file/URL opening to node-av/FFmpeg where native preparation is needed. Remove the proposed general text/binary streaming-loader extension, File/Web streamer classes, new URI/storage dependency and upstream Cascada loader work from Phase 6. Existing Cascada text loaders and their composition/caching remain unchanged. This supersedes the broader resource-loader proposal recorded earlier that day.

The native resource preparation helper opens the file/URL, inspects necessary metadata, selects its audio track and decodes/converts for the selected request. `.loadsAudio` always uses that native owner, even for WAV or matching samples, with no JavaScript file/fetch fallback. Main-entry PCM/WAV helpers and the optional converter's supported fallback operate on already-supplied bytes/streams through explicit preparers; they do not acquire file/URL resources. Preserve ordinary Transcriber's SDK encoded-file/URL behavior separately. Keep Web/Node/native-I/O adaptation private and native transports isolated in `casai/node-av`.

For native media preparation, retain the file path or URL until FFmpeg opens it. This preserves available seeking, native format probing and relative resource resolution for media playlists. Reuse FFmpeg's supported protocol/demuxer handling for HTTP(S), HLS/DASH and RTSP rather than implementing playlist polling, segment assembly, reconnect or session logic in Casai. Availability still depends on the installed native build and source. Do not convert every resource to a forward-only JavaScript stream before dispatch, buffer an entire recording to emulate seeking or silently spool it to disk.

A URL identifies the resource and ordinarily its top-level protocol. The media container/playlist is probed from content; the `https` scheme alone does not distinguish an MP4 file from an HLS manifest. The URI does not encode every native input setting: HTTP headers, authentication and RTSP lower transport options may require separate supported native options. Reuse those options through the narrow preparation boundary, including cancellation and application-controlled resource access, without a new protocol engine or guessing a transport from a filename. Ordinary component audio strings retain their existing meaning; explicit file/resource admission must distinguish paths/URLs from encoded audio.

**Track selection is independent of transport.** Keep native best-audio-stream selection by default, with the explicit zero-based container stream-index override already selected below.
