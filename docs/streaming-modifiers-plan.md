### Source evidence and type boundaries

Do not use the SDK's complete MIME-signature table as an encoded-versus-raw discriminator. Its two-byte MP3/ADTS prefixes are valid PCM16 samples: -1025 starts FF FB and -3585 starts FF F1. Retain those as positive raw controls. Use bounded, sufficiently strong container evidence for ambiguous finite byte/File inputs, with enough header structure to support the claimed container; RIFF, RIFX, RF64 and BW64 with a WAVE signature identify the WAV family. AVI, CAF, Wave64, FLAC, Ogg, ID3, ISO-BMFF and EBML also need controls for their own header structures. A prefix is not a general proof that all packets are valid. Explicit numeric sample representations remain raw even when their bytes resemble a header.

Validated self-description governs ambiguous byte/file inputs before applying headerless layout, without tracking whether a setting came from configuration or the call. A declared encoded File MIME cannot authorize sending it as raw merely because the header is inconclusive; reject that unsupported ordinary raw-input case. Empty/`application/octet-stream` MIME follows the same content/raw rules as bare bytes. Where source MIME and credible content evidence conflict, reject or use the established actual format; do not make a weak successful sniff authoritative. Headerless MP3/ADTS without sufficiently strong evidence cannot be distinguished reliably from arbitrary PCM bytes: document this boundary and keep `.loadsAudio` the explicit encoded-resource path.

**Selected `.loadsAudio` classification (2026-11-18; reconciled with the follow-up decisions).** A defined native demuxer override governs non-array inputs it can open. Otherwise classify only when a headerless layout is effective; without one retain the selected backend's normal probing and add no extra read.

## Recorded-audio translation

Treat support for prerecorded audio as a required use case, not a consequence of whether the SDK supplies a function named `translate`. The ordinary Translator's purpose is to accept a finite recording and return its completed translated audio, native source/translated text and metadata. Prefer one native speech-translation execution over an automatic Transcriber/LLMAgent/SpeechGenerator pipeline, which would require additional models and change the operation's behavior.

Implement and verify the following selected adapter contract; the prototype checks its types and integration rather than reopening byte admission or completed-audio representation:

- Separate the recording's encoding from result delivery. The native translation operation accepts raw audio chunks plus `inputAudioFormat`. The OpenAI translation endpoint requires 24 kHz mono signed 16-bit little-endian PCM; an MP3/WAV container is not raw PCM. Define finite recorded-data admission and use the explicit preparation contract below. Do not guess that arbitrary bytes are PCM or add an implicit codec dependency.
- Use one shared raw-audio input normalization for ordinary/incremental Translator and every transcription path using native streaming. Wrap finite bytes in a fresh stream per invocation; preserve native streams as supplied. Configured, inherited, shorthand, named, preparer-returned and tool-prepared bytes use the same rule. Preserve schema/preparation/cancellation ordering and claim the actual stream once immediately before dispatch. Keep input bytes unmodified; borrowed views require callers to leave them unchanged during the run. Do not introduce a second component or competing input wrapper inside the conversion utility.
- Pull finite bytes in chunks of at most 9,600 bytes, returning the final remainder unchanged. This fixed bound aligns mono/stereo 8/16/24/32-bit PCM frames and is 200 ms at OpenAI's 24 kHz mono PCM16 format. It needs no format-dependent branch and does not promise alignment for every possible provider format. Preserve every input byte without padding or truncation. Native caller streams retain SDK handling; do not add a universal rechunker or pacing layer. The review's recalled 15 MiB append cap was not established for translation; do not encode it as a contract.

| Input | Preparation |
| --- | --- |
| Raw PCM already matching the required format | Pass through without decoding, resampling or loading `node-av` |

The 2026-11-16 responsiveness decision requires all heavy audio processing off the calling thread. `pcm16ToFloat32`, `float32ToPcm16`, `readWav`, `writeWav` and `resamplePcm16` return promises. Finite calls share a lazy Node/browser pool capped at min(available logical processors, 4). Each worker processes its own ordered queue; choose the least queued worker and create another only while below that cap and existing workers are occupied. Resampling uses at least one consumer, with at least 262144 output samples per additional consumer, and submits at most 262144 output samples per job. A shared async iterator serializes preparation under one copy budget; consumers submit their next job only after completion. Short operations can run between those jobs, including on one core, without a reserved worker, priority API or whole-call queue. Other operations use one worker and prepare their borrowed input only after their queued turn starts. A worker failure closes that worker; independent calls retain their own results. Preserve global interpolation phase and boundary neighbors. The 2026-11-17 decision makes parallel PCM workers write disjoint ranges of one exact-size SharedArrayBuffer, publishing the completed Uint8Array only after every worker finishes. No growth protocol is needed for known finite output lengths. Single-job results transfer directly; multi-job nonshared results retain worker-based joining, including on single-core systems. Reuse already-shared byte views as read-only input, preserving offsets and excluding them from transfer lists. Keep borrowed input unchanged through processing/stream consumption; readWav may return a view into shared input. Each stream owns one ordered worker, separate from the finite queue; process roughly 32 KiB input blocks, preserve carry and deliver each result before reading more input. Preserve EOF, failure and cancellation cleanup. Add no public worker configuration or new dependency. Native preparation cleanup is idempotent across EOF, source cancellation/error and explicit disposal, including disposal after the consumer has already finished; release the same owned native handles and private bridge once. For nonseekable inputs, retain unread bytes and transfer reader/decoder ownership to the returned audio stream; cancel/release resources on preparation failure, cancellation and completion. Casai owns the resources it opens through preparation and SDK handoff; it closes them on abandonment or synchronous dispatch rejection. Applications retain ownership only of explicitly application-owned sources. This explicit ownership replaces the impossible promise that every encoded source remains unopened. Header/open failures can now occur during preparation; later decoding failures still propagate through native stream/result handling. Test bounded format lookahead separately from native stream-info inspection, plus no dropped/duplicated bytes, cancellation during inspection, pre-dispatch abandonment and normal EOF/error cleanup. Add no central resource registry or second decode pipeline.

**Owned-resource handoff:** `.loadsAudio` makes Casai the owner of resources it opens. Keep resource acquisition in the family media-preparation step using the invocation's merged settings and effective signal; a cached source renderer that sees only `(source, context)` cannot choose per-call `mediaSettings` or target overrides. Reuse shared schema/source resolution once, then prepare media once. Hold the prepared resource locally until dispatch actually accepts it. If preparation finishes but final validation/cancellation or a synchronous SDK model/capability check rejects, cancel/close that owned resource and preserve the original failure. Stream SDK functions can throw before their cleanup is installed; entering the SDK function is not itself ownership transfer. After a live result is returned, keep SDK/provider stream ownership and cancellation rather than wrapping or teeing the result. Prove the positive asynchronous-rejection case to avoid double cleanup. Direct caller-owned streams retain their existing native handoff contract, and authors still cancel independently prepared audio they abandon. No global registry, second controller or generic lifecycle framework is needed.

For supplied-stream preparation, close the private bridge as well as the native demuxer on early exit. The inspected native Node-readable bridge frees its listeners without destroying the supplied readable; demuxer closure alone does not prove that Casai's acquired Web reader or Node bridge was released. Keep cleanup with that private adapter, including cancellation before EOF and during a pending read, and assert the original source is cancelled and its reader lock released. Do not impose this preparation ownership on direct raw component inputs. After SDK handoff, test early provider finish and output cancellation against native adapters as well as asynchronous rejection; native SDK/provider ownership remains responsible for their input, including custom provider implementations.

#### WAV reading and writing

For a file-only transcription model, `inputAudioFormat` deliberately selects raw streaming and may be unsupported. Pass finite known-layout PCM to ordinary Transcriber with `sourceFormat` and no raw model target; the component privately prepares WAV for file transcription. No public WAV writer or node-av installation is needed.

For lightweight WAV preparation, reuse a suitable parser or a small bounded RIFF reader rather than a fixed 44-byte header assumption. Handle metadata chunks, padding, valid declared lengths and PCM/extensible-PCM metadata; return a view when no conversion is needed. Distinguish a legitimate zero-length data chunk from a producer's unknown-length convention; do not automatically treat every zero or `0xffffffff` length as all remaining bytes. Unknown-length/RF64 variants need verified parser support or the native converter, not silent misinterpretation. This baseline must not prohibit other easy supported WAV representations or sample conversions; avoid building a new general codec library.

Keep the matching WAV writer private to preparation. It takes finite PCM bytes and a known format and returns WAV bytes without guessing model output or transcoding. The supported PCM convention must be established from actual input/output facts, not inferred from the generic SDK format type. Write correct RIFF/fmt/data sizes and reject unsupported WAV representations. Reader/writer round trips preserve samples and rate, including empty audio and nonzero byte offsets. A simple canonical writer does not justify fixed-header assumptions in the reader.
