## Target API

The family contract summary below is an audit map; the matrix remains the full reference. Source selectors precede delivery/tool selectors, and `.asStream` never combines with `.asTool`.

| Family | Common call / named equivalent | Completed result / tool value | Default model-facing tool output |
| --- | --- | --- | --- |
| LLMAgent | Existing prompt/context/history forms and `.run()` | Full SDK result; tools return the completed text or parsed structured value | Native text/JSON; explicit Function tools may select and format files |
| Transcriber | `(audio, inputAudioFormat?)`; `.run({ audio, inputAudioFormat? })` | One `TranscriptionResult`; tools return `{ text, segments, language, durationInSeconds }` | Transcript text |
| SpeechGenerator | `(text, voice?)`; `.run({ text, voice? })` | One `SpeechResult` with optional collected format/usage; tools return the audio payload and actual format metadata | Native audio content, with optional user replacement |
| Translator | `(audio, inputAudioFormat, targetLanguage)` with unambiguous configured slots omitted; `.run()` uses those names | Collected native text/audio/metadata; tools retain actual text/audio | Translated text |

Audio-input families add `.withAudio`, `.loadsAudio`, `.withScript`, `.withFunction` and `.loadsScript`; speech retains its text-source selectors. `.loadsAudio` uses trusted `mediaSettings` and either raw `inputAudioFormat` or a configured encoded-file target. Loaded-audio tools require a trusted configured source; model arguments never replace it. Dynamic native resources use an explicit Function/Script workflow, while ordinary Transcriber tools retain SDK URL/download support. Config exposes the same source metadata without executing it. Other families participate only in shared modifier-only selection and the universal stream/tool exclusion; their native result shapes stay intact.

**Confirmed 2026-11-13:** ordinary `SpeechGenerator(...)`, `Transcriber(...)` and `Translator(...)` return completed results. They handle a model that requires native streaming internally, collecting that execution without requiring an application-authored Function wrapper. `.asStream` selects incremental result delivery; it does not force callers to expose a live result merely because the provider uses streaming. All three ordinary families support `.asTool`, including `Translator.asTool` and compatible source-prepared forms. This supersedes the earlier native-complete-only restriction on ordinary speech/transcription and the omission of completed Translator tools.

This Translator is specifically a **speech-to-speech** component. The installed SDK exposes only `experimental_streamTranslate`, but streaming input need not come from a microphone: a recording can supply a finite stream. The ordinary component provides completion/collection convenience over that operation. Ordinary text translation uses a non-streaming LLMAgent.

For ordinary text translation, use instructions such as: "Translate the supplied text into French. Preserve its meaning, tone and formatting. Return only the translation." Supply the source text as the agent's prompt. No separate text-translation component is needed.

```typescript
const translate = Translator.asStream({
  model,
  inputAudioFormat,
  targetLanguage: 'fr',
});
const result = await translate(audioStream);
```

Here the application supplies a native translation model, audio format and fresh raw-audio stream. The call returns the native live result. Named invocation is also supported through `translate.run({ audio: audioStream })` as an alternative to the last line, using the stream once.

The ordinary form uses `Translator({ model, inputAudioFormat, targetLanguage: 'fr' })` and waits for the finite recording's completed result. Both Translator modes and every transcription path using native streaming accept reusable finite raw audio bytes (`Uint8Array`, including Buffer, and `ArrayBuffer`) as well as native audio streams. `.asStream` changes result delivery, not finite-byte admission. Complete delivery requires a source that ends; it does not need a distinct byte-input adapter. Encoded-file versus raw-audio format requirements still belong to the selected native operation and explicit preparation.

Expose the same API through named imports and `create`. Remove the three old public `Streaming...` exports and their public component-kind names; keep no compatibility aliases for these unreleased names. Native SDK names and experimental status stay unchanged.

Source modifiers come first, followed by either `.asStream` or `.asTool` where supported. **Confirmed 2026-11-13:** no component combines `.asStream` and `.asTool`, including through parents or Config fragments. This removes the previously selected prepared-streaming-transcription exception; it also applies to future Template streaming. Script/Function schema-declared stream collection and native third-party SDK tools are separate contracts and remain unchanged. The modifier-only decision below also rejects direct configuration flags rather than treating them as an alternative way to select a mode.

```typescript
SpeechGenerator.asStream({ model });
SpeechGenerator.withTemplate.asStream({ model, text: 'Hello {{ name }}.' });
Transcriber.withFunction.asStream({ model, audio: openAudio, inputAudioFormat });
Translator.withFunction.asStream({ model, audio: openAudio, inputAudioFormat, targetLanguage: 'fr' });
Translator.withFunction.asTool({ model, audio: openRecording, inputSchema: recordingSchema, inputAudioFormat, targetLanguage: 'fr' });
```

These illustrate the planned factory paths; dependencies are application-supplied. Do not add reverse modifier orders such as `.asTool.asStream` or `.asStream.withFunction`.

**Universal rule:** no source form of any `.asStream` component is tool-compatible. This applies to every family, including LLMAgent, Config and future Template streaming; templates, scripts, functions and loaded sources create no exception. Ordinary prepared `.asTool` forms and calling registered tools remain separate supported capabilities.

### Modifier-only selection

**Confirmed 2026-11-14:** all Casai modifier functionality is selected through factory/Config modifiers, never duplicate public configuration properties. This applies across all component families and reusable Config fragments, including future modifiers. Source selectors already follow this rule; extend it to `.asStream` and `.asTool` during deliverable A. Remove public `streaming` and `asTool` settings instead of correcting the matrix's erroneous `streaming: false` to another public flag type. Retain the existing rejection of the retired `promptType` setting. Add no replacement mode property, aliases or reverse/disable settings.

The selected API is `LLMAgent.asStream({ model })`, `Function.asTool({ inputSchema, execute })` and compatible source-first chains such as `Transcriber.withFunction.asStream(...)`. `LLMAgent({ model, streaming: true })`, `Function({ asTool: true, ... })` and `Config({ streaming: true })` are invalid. Explicit `false` or `undefined` does not make a removed property valid.

Preserve modifier state as internal structural metadata, reusing the existing source-mode approach. Modifiers set it; ordinary configuration spreads, parent components and Config intermediates retain it. Preserve the existing semantics: source selectors can explicitly replace the inherited source, while inherited streaming/tool modes cannot be disabled and their combination remains invalid. Store streaming and tool enablement in independent enumerable structural symbol keys, present only when enabled; ordinary configurations emit neither disabling values nor empty mode objects. A single replaceable mode key would lose one enablement in `{ ...live.config, ...tool.config }` and incorrectly admit the combination. Both spread orders must retain both selections for the existing validator to reject, and spreading an ordinary config must retain any enabled mode. Reuse the cross-copy symbol/declaration strategy already used for sources. Do not expose named `.config.streaming`/`.config.asTool` fields as a replacement public control or require applications to author internal metadata. Keep inferred declarations portable across installed/source consumers and independently loaded package copies; do not introduce identity branding or a second configuration system.

Reject removed named properties in authored configuration and invocation settings before merging or dispatch, including own/inherited declarations and explicit undefined, so valid parent metadata cannot conceal an invalid child setting. Validate the original settings object before spreading it or filtering undefined values; either normalization can erase a forbidden declaration. Apply the same rule to incomplete Config fragments. Copied internal source/tool/stream metadata is configuration-only too: reject it in `.run()`, `resume()`, native Agent methods and other applicable named invocation settings, directing callers to derive a component. Do not silently ignore it when string-key settings filtering drops symbols. Same-named fields inside declared application schemas/context remain data and do not select modifiers. Keep all modifier metadata out of SDK requests and model-facing tool arguments. Preserve native SDK Agent `.generate()`/`.stream()` methods and schema-declared Script/Function streams: these are existing execution contracts, not alternative Casai configuration selectors.

Check removed names on structural raw parents (`{ config: settings }`) before copying them too; already-created components are not the only admitted parent form. Reuse the cheap selector check at the original-object boundary without revalidating schemas or adding parent branding.

This decision supersedes the direct-flag, public `.config.streaming` and named sticky-flag implementation requirements elsewhere in earlier plans/reviews. Phase 6 owns the runtime/type migration for every affected family and checks that future modifiers cannot acquire parallel property-based selectors. The matrix tracks the selected contract immediately through its documentation-only projection, with a work-in-progress marker until implementation. Deliverable A replaces that projection with production declarations and removes the marker after acceptance checks.

### Audio resource modifier

**2026-11-13 plan consolidation:** use `.loadsAudio`, following `.loadsText`, `.loadsTemplate` and `.loadsScript`. It describes how a component obtains its input; it is not a method that performs a separate load before invocation. Do not add `.loadAudio` or `.load` aliases. Support these paths on both `Transcriber` and `Translator`, through named exports and `create`:

```typescript
Transcriber.loadsAudio(transcriberConfig);
Transcriber.loadsAudio.asStream(transcriberConfig);
Transcriber.loadsAudio.asTool(mediaToolConfig);
Translator.loadsAudio(translationMediaConfig);
Translator.loadsAudio.asStream(translationMediaConfig);
Translator.loadsAudio.asTool(translationMediaToolConfig);
```

These are planned factory-path illustrations with application-supplied configuration, not executable current-API examples. SpeechGenerator has no audio input and gains no `.loadsAudio`. Config exposes the same selector and compatible source-first chains as an incomplete reusable fragment; completion must select a compatible audio owner. No `.asStream`/`.asTool` combination is allowed. Preserve one selected source mode, structural symbol metadata, ordinary Config merge/override laws and safe source-mode unions; this is not a chain of multiple source preparers.

In this mode the existing `audio` source field accepts a file path/media URL (`string | URL`), supplied encoded bytes (`Uint8Array | ArrayBuffer`, including Node Buffer) or a `ReadableStream<Uint8Array>`. A source string explicitly means a resource reference, never base64 or executable text. Strings in `.loadsAudio` remain resource references; binary sources are inspected/prepared through the same native owner. Ordinary audio mode retains its native supplied-data meanings. Use `.withAudio` to explicitly reset an inherited preparer or `.loadsAudio` selection to that ordinary mode. Add it to Transcriber, Translator and Config, with compatible completed/tool/stream chains. It selects the existing literal source mode; it adds no new conversion mode or reset flag. Clear incompatible inherited preparation-only settings under the ordinary configuration rules. Keep audio selectors out of text-family modifier tables. Build the shared prepared-mode list only from script/function/loaded-script selectors; `.withAudio` is literal input, and neither audio-only selector may leak through the current textModifiers spread. Configure a reusable resource or supply/replace it on each ordinary call; named calls use `.run({ audio: resource, ...settings })`. Source shorthand remains primary, including path/URL unions and inherited defaults. Paths/URLs are opened afresh per invocation; immutable supplied finite bytes can be reused. Supplied streams remain single-use, including when configured or inherited. Preparation may consume them for necessary inspection; preserve read-ahead and do not promise automatic replay or reuse detection beyond the existing native-input identity guard. Constructing a component does not open or decode media. `.loadsAudio` needs no Cascada `loader` setting and must not reuse the generic named-script/text requirement for one. Today the `-name` mode suffix drives that requirement in three places: factory validation (`mode.endsWith('-name')`), requiredness types (`${string}-name`) and the Cascada renderer's loaded path. Use the internal source identifier `audio-resource`, outside that suffix convention; the existing loader rules then exclude it without special cases. Consequently no loader root, search path or fallback applies: a relative path is resolved by native file opening against the process working directory. Document this, because `.loadsText`/`.loadsTemplate`/`.loadsScript` names resolve through loaders, and tool recipes must authorize the resolved location rather than the relative string.

Use `mediaSettings.track?: number` in configuration and named invocation settings, with no additional positional slot or top-level `track` alias. Omission chooses the native best audio stream; a supplied non-negative integer selects that zero-based container stream index. Invalid, missing, non-audio or unusable explicit selections fail; usability follows the required native copy/decode/encode path for the resolved target. Retain ordinary configuration clearing and call-time undefined-as-omission rules; no new sentinel is needed. Strip preparation controls from SDK model requests, preserving same-named application/context data as data. Native input options and credentials remain trusted preparation settings, supplied through configuration or trusted named invocation; the native backend connection stays internal. An explicit preparer may map validated application choices to preparation settings. Follow the [media settings contract](#media-input-settings) and [media authentication/access boundary](#authentication-and-media-access), including fresh per-call credentials and separate model headers.

Completed `.loadsAudio.asTool` components require a configured `audio` source in the finished component, including inheritance. Reuse the configured-resource rule of `.loadsText.asTool`; do not add a public-resource exception to tool source requiredness or literal-input dispatch. Reusable Config fragments remain incomplete. SDK descriptor/injected tool execution uses the trusted configured source. Closed public schemas may still declare application/context fields for supported callbacks, including a field named `audio`, but neither that parsed value nor defaults/transforms/private context replace the resource. Configured source values stay out of advertised public defaults and tool schemas. Undeclared argument rejection and parsed-value handling use the existing boundary; no new schema inspection or public-field ban is needed. Trusted ordinary calls and `.run({ audio, ... })` retain their normal explicit source overrides. For model-selected recordings or per-call credentials/track settings, expose an explicit Function/Script workflow that resolves and authorizes the application input, then invokes an ordinary `.loadsAudio` component through `.run()`. Explicit preparer payloads remain application-defined. Reuse existing binding/injected execution, cancellation and completed result projections; finite input/native completion remains required.

- Its source renderer is an identity step. Family media preparation then runs with the merged settings, as described under [owned-resource handoff](#header-inspection-metadata-and-cleanup).

### Audio shorthand

Unmodified factories preserve inherited source and delivery metadata. An explicit `.withAudio` replaces the inherited source interpretation; it does not reset an inherited `.asStream` or `.asTool`. This is the same inheritance rule as other families. Use an unmarked configuration parent to share settings across delivery forms; do not add an audio-only inheritance error.

Secondary positional slots belong to the audio operation, independently of `.asStream`. Ordinary/raw Transcriber accepts `(audio, inputAudioFormat)`; encoded-file transcription uses `(audio)` without a format. Both Translator delivery modes accept `(audio, inputAudioFormat, targetLanguage)`. Speech retains `(text, voice?)`. In `.loadsAudio`, the audio slot accepts the resource, encoded bytes or byte stream; a supplied `inputAudioFormat` is the model target, never the source demuxer. Omit configured slots only under the existing unambiguous-role rules. `Translator.loadsAudio` has a genuine same-type collision: both the resource and `targetLanguage` can be strings. A leading string is therefore always the resource. With a configured resource, a language-only call uses an `undefined` placeholder, `translate(undefined, undefined, 'fr')`, or `.run({ targetLanguage: 'fr' })`; never classify a string as a language code by its contents. Transcriber's object format does not collide with its string/`URL` resource. Preserve prepared context ordering and explicit placeholders where context and format are both objects; do not guess from field names. Source demuxer, track and credentials gain no positional slots; the backend connection is internal. Tools resolve execution format/language in trusted configuration; their model arguments remain declared input/preparation data.

## Behavior to preserve

- Ordinary calls and `.run()` on a streaming component resolve to its native live SDK result. They do not collect the output before returning.
- Complete transcription retains its existing tool projection regardless of the native execution path. ## Recorded-audio translation

Treat support for prerecorded audio as a required use case, not a consequence of whether the SDK supplies a function named `translate`. The ordinary Translator's purpose is to accept a finite recording and return its completed translated audio, native source/translated text and metadata. Implement and verify the following selected adapter contract; the prototype checks its types and integration rather than reopening byte admission or completed-audio representation:

- Separate the recording's encoding from result delivery. The native translation operation accepts raw audio chunks plus `inputAudioFormat`. Define finite recorded-data admission and use the explicit preparation contract below. Do not guess that arbitrary bytes are PCM or add an implicit codec dependency.
- Use one shared raw-audio input normalization for ordinary/incremental Translator and every transcription path using native streaming. - Pull finite bytes in chunks of at most 9,600 bytes, returning the final remainder unchanged. It needs no format-dependent branch and does not promise alignment for every possible provider format. Preserve every input byte without padding or truncation. Preserve native failures for missing finish, insufficient output, transport errors and cancellation. Translation currently accepts any emitted audio part or nonempty final translated text at finish; do not replace this with Casai's idea of valid audio.

For integer downsampling, carry incomplete groups between reads and send only whole groups to the worker interpolation kernel. For mono PCM16 the group is `2 * (inputRate / outputRate)` bytes; retain fewer than one group, including a possible split sample byte. At EOF process remaining complete samples with the same SDK rounding rule as finite conversion. An odd sample count is valid; an unmatched final byte is incomplete PCM16 and must fail the helper rather than be padded or dropped. This does not add content validation to raw component inputs. Other ratios and upsampling remain outside this SDK stream path; never independently resample arbitrary chunks or buffer an unbounded stream.

Copy the small carried remainder so it neither retains a large backing buffer nor becomes detached when a processed block is transferred. Process at most one bounded block per worker request. Retain the current borrowed producer chunk until its blocks have been consumed; never copy or compute a huge chunk in a single calling-thread turn. Source buffers must remain unchanged while borrowed.

Use a demand-driven `ReadableStream` with zero prefetch for that adapter. Acquire the input reader on the first output read; do not create a `pipeThrough` pipeline during preparation, since it can read eagerly. Release the reader at EOF, error and cancellation, propagate cancellation to the source, and handle cancellation during an awaited read without enqueueing afterward. A pre-read cancellation cancels the source without acquiring its reader or opening conversion resources. Test against whole-buffer SDK conversion for irregular chunks, split samples, odd offsets, empty/single-sample inputs and all EOF remainders; include source failure and cancellation before/during reads. This is a bounded stream adapter around the same worker kernel, not a general resampling or stream-lifecycle framework.

Prefer generated tiny fixtures over large downloaded recordings. Create deterministic raw PCM in test code from independent known samples: silence, impulses, ramps, bounded tones, distinct channel/track patterns and deliberate chunk boundaries. Most codec fixtures need only about one or two seconds. In isolated native setup, encode/mux those samples through supported native APIs into representative WAV/FLAC/MP3/AAC/Opus containers, multi-track/no-audio files, and seek-dependent or playlist inputs; generate a small synthetic video stream only for audio-extraction tests. Do not use the Casai helper under test to generate its sole expected output. Compare against known sample counts/values, native reference execution and decoded metadata; account for documented codec delay/padding and avoid byte-equality assertions on lossy encoding or variable container headers. Derive truncated/malformed and odd-offset variants from these fixtures. Include generated ffconcat uploads referring only to test-owned local/network resources, with unrestricted-native controls, default-denial assertions and trusted-override positives. Use tiny test-configured bounds for size-limit negatives instead of uploading large files.

Provider speech tests need intelligible speech, not tone fixtures. Reuse a short redistributable recording with known words, or generate a short TTS fixture once during explicit setup and cache it with its text, format, provenance and hash. Target roughly five to ten seconds with distinctive opening/closing phrases; add only the longer/multi-sentence case needed to exercise native finish/tail behavior. A fixture should not require a fresh paid generation on every test. Test synthesized speech generation itself separately. Keep assertions semantic and tolerant of harmless punctuation/nondeterminism while detecting lost tails, empty output, wrong language or corrupted audio. Public fixture URLs must not be a runtime dependency: vendor small permitted originals or generate/cache them in test-owned temporary directories and serve transport cases locally. Record any fixture license/source and required native features.

Use bounded tests and small explicit inputs; reuse successful evidence after unrelated changes, while rerunning affected stages after fixes. Real native/provider acceptance remains mandatory before completion. LGPL artifact provenance/compliance is an additional release check: passing audio tests alone cannot certify a build's license.

Use focused mutations to show that runtime tests detect reintroduced named selector admission, wrong-operation dispatch, lost inherited/copied modifier metadata, metadata leaking into SDK requests and incorrect tool admission. Type mutations must catch reintroduced flag properties, weakened one-shape checks and unrelated fields. Reuse existing native probes rather than retesting unrelated SDK behavior.

Follow [AGENTS.md's test and compiler rules](../AGENTS.md#tests) and [test commands and performance](../tests/README.md). Compare source/declaration diagnostics and compiler cost with the baseline and existing budgets.

Validation order:

1. Selected mock files through `npm run test:file -- <files>` and focused type checks while implementing each family.
2. `npm run test:matrix` for generated matrix examples; extracted guide examples and declaration-consumer fixtures through the existing type checks.
3. `npm run check` once the complete change is integrated, covering type checks, `test:matrix`, lint and mock coverage.
4. Installed/bundled consumer verification and applicable mutation checks, reusing successful evidence already covered by the final gate.
5. Run the maintained native integration stage and explicitly selected paid `test:live` audio stage from the [acceptance suite contract](#maintained-acceptance-suites-and-small-fixtures). Cover all supported native operation paths, resource preparation and completed tools, with finite recordings and recognizable beginning/end content. Check metadata, transcript/translation tails, native finish behavior, elapsed time and sending rate. For transcription, record the relation between the single commit and completion/item events rather than assuming one item covers arbitrary recordings. These cases establish no unlimited-duration guarantee. Preserve SDK close/drain handling; add no speculative pacing, extra commits or multi-item collection. Paid calls are authorized for this implementation acceptance work; a documentation-only plan update does not itself require them.

Follow [the review process](review-process.md): inventory the whole public surface, trace downstream consumers, compare native behavior, and test interactions and meaningful mutations. Record findings and process improvements. After corrections, complete a subsequent full review pass with no important unresolved findings before declaring implementation complete.

## Completion criteria

- B uses upstream node-av-lgpl under the documented node-av alias. Every beta/final release requires real integration/package validation on the exact LGPL artifacts under the [selected policy](#native-backend-selection). Installation guidance, supported-platform provenance and applicable distribution materials are complete. Preserve explicit GPL selection; nonfree remains unsupported. Track implementation/acceptance separately from release readiness. Package availability is resolved, but until native/platform/distribution evidence is complete, keep those release gates outstanding and do not describe the whole phase as fully complete.

- Future guide and implemented guide/matrix documentation explain format auto-detection, overrides, raw input, probing/seekability, source versus target formats, explicit targets when model requirements are unknown, conversion behavior and the SDK/native path distinction; examples and reference applicability agree.
- File transcription copies compatible audio using the primary or first compatible alternative, otherwise converts to the explicit primary target within native encoder/sample constraints. No universal lossy/downsample/mono/PCM16 conversion or automatic lossless-target selection is added. Exact public types and helper signatures are finalized with implementation, documented from the resulting declarations and verified through consumers; no separate planning-stage prototype approval remains.
- B exposes the confirmed `mediaSettings: { track, format, options }` input contract across its source/helper/Config/named-call consumers, with native option pass-through, no aliases or new deep merger, optional-peer-safe declarations and the required authentication/namespace/override checks.
- The three replacement APIs and supported source/tool combinations work through named imports and `create`.
- Every Casai modifier is selected only through factory/Config modifiers. Public `streaming`/`asTool` flags are removed, retired `promptType` remains rejected, and no replacement public selector is added. Internal metadata preserves source/tool/stream inheritance and copying across all families; guides, matrix inventories and declarations agree. Native Agent methods and same-named application data retain their separate contracts.
- Inheritance, `.config`, shorthand, `.run()`, callbacks and emitted types agree on the selected operation.
- All component families and Config retain exact shape-based type admission. Casai-owned streaming controls are enforced at runtime without changing the native SDK validation policy.
- Deliverable A preserves native execution/completion semantics, supports ordinary completed audio calls/tools over streaming-only models, removes public streaming-tool combinations, and adds shared byte normalization plus completed Translator and its tool form. LLMAgent tool values remain unchanged, and explicit Function tools can compose native output/files without automatic media-schema processing. Already-prepared PCM remains usable without `node-av`.
- Deliverable B provides `.loadsAudio` on Transcriber/Translator and compatible Config chains, numeric `track`, direct file/URL media preparation and internally adapted byte streams, main-entry PCM/WAV helpers and finite/integer-stream SDK-compatible conversion, plus isolated native conversion that requires node-av for every native-helper invocation, including supplied bytes/streams. `.loadsAudio` requires native installation with internal loading; it has no resource-loading fallback. The native media-input prototype verifies the selected source API, protocols/options, [authentication/access boundary](#authentication-and-media-access) and separate track selection; stream adapters remain internal and existing Cascada text loaders remain unchanged. Absent-peer builds/source consumers/bundles, browser/Node conditional loading and the upstream Cascada browser-packaging prerequisite, real-package interface checks, header/read-ahead and transport cleanup, documented quality/costs/platforms and mock/native evidence pass. Its evidence is tracked separately from A; completing A alone does not complete the phase.
- Old public names are removed from active declarations, package output, guides and examples; historical records remain intelligible.
- The matrix includes `.asStream`, valid combinations, working embedded sources and regenerated full API reference data. Actual local result types, native setting alternatives and conditional experimental dependencies agree across reference consumers and examples. Remove each work-in-progress marker as its scoped implementation is verified, replace documentation-only aliases/projections with production extraction, and enable the corresponding private type/runtime coverage; keep markers for any remaining pending work.
- The maintained local, native and paid-provider acceptance suites pass for all claimed Phase 6 behavior, using small generated/licensed fixtures. At least one named real-provider audio tool-result route is proven; serialization-only evidence cannot close Phase 6. The final complete review passes; native limitations and any unverified platform, provider or release requirement remain explicit blockers to the corresponding completion claim.
