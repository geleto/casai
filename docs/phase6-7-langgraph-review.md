## What survives a retry or disconnect

The November 27 follow-up compared submitting the same recording again, reconnecting to an existing execution, and playing output a second time. Tests in the earlier comparison generally used a fresh input per operation, completed a well-formed stream and connected one successful listener. They could miss a second request that succeeded with zero bytes or a listener that consumed someone else's only opportunity to play the reply.

The SDK and Casai had independent ownership records. Both file operations now register acquisition of the original reader with Casai. Failed file validation leaves the input available. Finite recordings still support retries. Mastra's file caller creates a new reader from saved bytes per attempt. ## 1. Give late realtime tool results a turn owner

**Reproduction.** In Chromium, connect the installed AI SDK's public realtime session to a controlled turn-based WebSocket relay. Let response A request `lookup-A`, then finish response A with its tool still pending. Send a second user utterance, “cancel that and tell me the time.” Deliver `response-created` and the first text delta for response B. While B is active, resolve A's tool. The browser sent one `function-call-output` for A followed by an unqualified `response-create`. The single-turn control sent the same pair. The existing interruption test releases the tool after the next speech onset, before a distinct response B has started. [Existing browser test](../tests/fixtures/browser-media-contracts.test.mjs) · [Native response scheduling](https://github.com/vercel/ai/blob/c39dedf99de495531017b7805dd7a99209798828/packages/ai/src/realtime/realtime-session.ts#L722-L761)

The published session can send a request to generate while the provider is already answering the newer question. The captured evidence ends at that outbound request. The SDK candidate submits the late tool result once against its original call. It requests an automatic continuation only while that reply still owns the turn. If an application needs a late result announced, it can schedule an explicit announcement after the current reply. Automatically queuing every old completion can revive a request the user has superseded. A provider-managed transport owns its own continuation. [Native tool execution and event handling](https://github.com/vercel/ai/blob/c39dedf99de495531017b7805dd7a99209798828/packages/ai/src/realtime/realtime-session.ts#L917-L1059)

**Protect the business action separately.** Two concurrent calls to the public `VoiceAgentBackend.executeTool` with the same `reserve` call ID executed a counter twice. In a real LangGraph run, resuming an `interrupt()` re-entered the node and ran the code preceding the interrupt twice. For a reservation or payment, reuse the application's durable idempotency mechanism on its authenticated tool route. Bind the key to the user or tenant, conversation and call ID, and verify the operation and arguments before returning a previous outcome. Use downstream idempotency or a transaction when the effect can succeed before its result is recorded. A read-only lookup can simply retry. Apply the guide’s existing approval-replay advice to the voice endpoint. Keep this state with the application’s business action. [Casai approval and replay guidance](matrix/documentation.md#guide-concurrency-ordering-and-recovery) · [LangGraph interrupt and side-effect guidance](https://docs.langchain.com/oss/javascript/langgraph/interrupts)

## 2. Publish a streaming chained-voice example

The LangChain guide uses partial transcripts for captions and a completed utterance to start the agent. The distinction matters when implementing it with Casai. In a loopback run through the Deepgram adapter candidate and Casai, Nova returned two `transcript-final` events for one command. “turn on” carried `speechFinal: false` and “the lights” carried `speechFinal: true`. Dispatching on every final starts two agent calls. Waiting for `result.text` waits for the recording session to end. Collect stable segments for the channel until the utterance boundary, then submit once while capture continues. With Flux, an eager ending followed by `TurnResumed` was still provisional. The actual `EndOfTurn` for that turn index produced one final, including when the fixture repeated the terminal packet. An application that requires explicit confirmation can use push-to-talk or a user commit instead. [LangChain voice example](https://github.com/langchain-ai/voice-sandwich-demo/blob/0c798661cd1766ae2b4f5c23cda0d3d07012cbfd/components/typescript/src/assemblyai/stt.ts#L38-L54) · [Deepgram endpointing and interim results](https://developers.deepgram.com/docs/understand-endpointing-interim-results) · [Casai SDK candidate](../tests/fixtures/ai-sdk-transcription.patch)

Give the microphone session its own lifetime and each reply its own cancellation signal. Feed only the designated assistant's text into one streaming speech call. In a two-node LangGraph fixture, `streamMode: "messages"` returned both the planner's “internal estimate” and the speaker's “your total.” Selecting `metadata.langgraph_node === "speaker"` before TTS isolated the intended text. In Cascada, bind the speaking callable explicitly. This decision can be made as the first token arrives. Selecting on a final stop reason requires waiting until generation ends. [Graph stream modes and filtering](https://docs.langchain.com/oss/javascript/langgraph/streaming) · [Voice example's agent loop](https://github.com/langchain-ai/voice-sandwich-demo/blob/0c798661cd1766ae2b4f5c23cda0d3d07012cbfd/components/typescript/src/index.ts#L156-L211)

This Cascada body was executed with `answer = LLMAgent.asStream({ model })`, `speak = SpeechGenerator.asStream({ model })` and `prompt` set to the committed transcript.

```cas

return speak(reply.textStream)
```

The first audio bytes reached the caller while the model's second text token was still withheld. Direct JavaScript gave the same result, with one TTS request in each run. The executable Casai workflow cancels the old agent, synthesis and local playback on new speech while continuing to read microphone events. It uses the speaker’s native full stream to forward text deltas and propagate late model errors. The demo waits inside its agent output loop before polling the next upstream event, and its producer queue can keep growing. Borrow the turn boundary and the streaming composition. Keep the speaker and microphone independently cancellable. A chained reply buys provider choice and explicit text control at the cost of endpointing and another model boundary. Keep native speech translation and realtime voice on their dedicated paths. ## 3. Use a streaming HTTP response for ordinary browser speech playback

For applications that already serve audio, expose the authorized reply's `SpeechGenerator.asStream` byte stream with its actual content type and give the browser audio element that URL. LangGraph's React player uses incremental PCM playback for PCM and WAV. For an inline MP3 its element strategy awaits an object URL backed by the completed Blob. Adopting that strategy would add a framework dependency and delay playback until EOF. [Player selection](https://github.com/langchain-ai/langgraphjs/blob/e58f0c6d21882af337bf4b7a652208e5c619b705/libs/sdk-react/src/use-audio-player.ts#L397-L415) · [Element playback](https://github.com/langchain-ai/langgraphjs/blob/e58f0c6d21882af337bf4b7a652208e5c619b705/libs/sdk-react/src/use-audio-player.ts#L957-L973)

A local HTTP handler streamed actual MP3 frames through Casai's speech result. With a 100,312-byte prefix Chromium advanced past 150 ms of playback while the response tail was withheld. With 12,769 bytes of the short fixture it did not advance past that point in 1.2 seconds and played to completion after release. Browser buffering matters. Use this low-complexity route for compatible encoded speech when progressive playback suffices. Use a playback path with explicit PCM scheduling for a tighter latency requirement. Measure first playback with the intended browser and codec. Make the URL refer to one reply so a media-element retry cannot generate and bill a second reply. ## 4. Preserve incremental bytes and file metadata

The PCM comparison sent an inline handle's byte stream and known input format to `Transcriber.asStream`. Casai produced a partial transcript after the first graph delta and before the graph message finished or its Blob resolved. A MIME such as `audio/pcm` alone does not establish rate, channel count or sample representation. For a finished file, keep the original filename alongside its Blob. The completed PDF Blob had no `name`. Use the published or candidate file route appropriate to the chosen model. Local preparation handles an explicit track, edit or required format. The LangChain Whisper loader documents a file-to-document operation. [LangGraph media handles](https://github.com/langchain-ai/langgraphjs/blob/e58f0c6d21882af337bf4b7a652208e5c619b705/libs/sdk/src/client/stream/media.ts) · [Whisper file loader](https://docs.langchain.com/oss/javascript/integrations/document_loaders/file_loaders/openai_whisper_audio) · [Casai file and recorder routes](streaming-modifiers-plan.md#provider-audio-request-checks)

**Choose one representation per consumer workflow.** A URL-backed handle issued two GETs when the application read `.stream` and then `.blob`. A changing fixture returned byte 1 to playback and byte 2 to the saved Blob. Use an immutable asset or materialize once if playback and storage must agree. Inline handles have a different cost. Sending 256 deltas of 4 KiB produced a 1 MiB file and 128.5 MiB of cumulative prefix copies inside the assembler, even without reading `partialBytes`. The counter measures total bytes copied across all deltas. Use a direct binary stream for sustained recording or synthesis. The Casai workflow passes the byte stream directly to its consumer. When replay is required, the application can write that same stream to an immutable asset. [Inline accumulation](https://github.com/langchain-ai/langgraphjs/blob/e58f0c6d21882af337bf4b7a652208e5c619b705/libs/sdk/src/client/stream/media.ts#L323-L340) · [URL fetch paths](https://github.com/langchain-ai/langgraphjs/blob/e58f0c6d21882af337bf4b7a652208e5c619b705/libs/sdk/src/client/stream/media.ts#L521-L585)

## 6. Persist asset references for tool media that must survive a later turn

LangChain's `ToolMessage.artifact` separates application data from what the chat model sees. It does not guarantee that the application data survives a checkpoint in its original form. A tool returned the model text “caption” and an artifact containing an asset ID, Blob and typed bytes. ChatOpenAI received only the caption. After a real graph invocation and `getState()` with the JavaScript `MemorySaver`, the ID survived, the nested Blob became `{}` and the nested `Uint8Array` became a plain object with numeric keys. This result applies to nested tool artifacts in the tested saver. [LangChain tool artifacts](https://docs.langchain.com/oss/javascript/langchain/messages#artifact) · [Checkpoint serializer](https://github.com/langchain-ai/langgraphjs/blob/e58f0c6d21882af337bf4b7a652208e5c619b705/libs/checkpoint/src/serde/jsonplus.ts)

For a replayable voice memo or generated image used only by the UI, store the media once and return an application-owned immutable asset ID, content type and filename. Use the existing `toModelOutput` to give the language model the caption or specifically requested attachment. For speech, a regular `SpeechGenerator` inside an application tool can write to storage directly. The built-in speech tool already makes a base64 result by the time its formatter runs. Realtime `VoiceAgentBackend.executeTool` returns execution output directly, so the route itself must choose the small JSON result it sends back. Keep inline bytes for short-lived calls where the receiver needs the content. Durable storage adds retention and access-control work, so introduce it only for workflows that need replay. ## Streaming when the consumer pauses

A graph node using LangGraph's `custom` mode delivered a progress value while the node was held open. An explicit AI SDK tool supplied to Casai's `LLMAgent.asStream` likewise delivered its first preliminary result while its final value was withheld. Only the final output entered `messageHistory`. Use a native SDK tool for live model-tool previews, or a Cascada workflow with an application-owned progress callback for work outside a model tool. Finite Script and Function tools can keep their documented completed result. A second event protocol would add two ways to observe the same tool. [LangGraph streaming modes](https://docs.langchain.com/oss/javascript/langgraph/streaming) · [Casai tool output](matrix/documentation.md#guide-stream-schemas) · [Executed native preview](../tests/MediaHandoff.unit.test.mjs)

For voice, test open input, first provider output and first playback independently. Mastra's generic AI SDK voice adapters collect input before provider dispatch. Speechify streams the audio response and the LiveKit integration supports live voice. The LangChain voice example uses live provider connections, but its graph progress stream alone cannot establish when a particular speaker plays audio. Casai can use one listener for a long reply when replay and conversation history are unnecessary. The executed example selects that SDK operation explicitly and keeps the same per-turn cancellation and Cascada composition.
