## Follow-up decisions and remaining choices

1. **Structured rendered sources - implemented:** the user selected positional arrays as literal history on all agents. Authored message-array templates use configuration or `.run({ prompt: templateMessages, context })`; history uses the positional history slot or named `messageHistory`. String shorthand remains newly authored source. Preserve all explicit text slots in an authored array, rather than guessing which messages have executed. Native messages carry no such marker. Plain agents follow the same rule; new message arrays use named prompt settings, and two-array shorthand is not supported. This supersedes the earlier positional structured-template source convenience. The installed SDK rejects system messages in prompt arrays by default, with `allowSystemInMessages: true` as its native opt-in; the multi-message examples use supported user messages.
2. **New SDK settings - implemented:** the user selected native unknown-setting behavior. Forward native settings after excluding Casai-owned and explicitly prohibited fields. This avoids maintaining an SDK setting whitelist and supports additions within the peer range. TypeScript continues to reject typos, but JavaScript typo detection becomes native behavior. Existing fixed settings, source/payload separation and private-context controls remain Casai-owned.
3. **`none`/null - verified:** the installed Cascada lexer already recognizes both literals as null, and template/script probes agree. Retain native null unless a concrete invocation convenience is selected. Omit named settings rather than passing a null placeholder: `image.run(mask=newMask)` retains the configured prompt and images, while `image.run(prompt="sunset")` changes only text. A narrower alternative would treat null as omission only in specified positional placeholder slots. Do not globally normalize context/payload values or native settings such as `turnDetection: null`.
4. **Ordinary calls on plain tools - implemented:** the user selected direct payload calls such as `embedTool({ input: "hello" })`. Reuse preparation for ordinary shorthand, named calls and injected tools. Precedence is explicit invocation source, then declared parsed tool input, then configured source. Example: `embedTool.run({ context: { input: 'hello' } })` works and applies the field transform. This is a specific plain-tool rule, not permission to copy arbitrary payload properties into configuration. Authored primitive/array/media source overrides remain available with their separate payload; use `.run()` for structured object source overrides. Ordinary calls preserve native results; injected tools retain their projections. Script and Template support both registered helpers and context-held callable tools.
5. **Video/batch scope - deferred by the user:** use the native SDK directly for now. These APIs have start/status/result/cancel lifecycles that deserve separate component design. A future wrapper should return the native serializable operation/batch reference and accept it in later status/result/cancel methods, without storing the current job in the component. The installed SDK already uses this model.
6. **Upstream Cascada work:** the private-value diagnostics and lost nested function properties need upstream changes. Decide whether to take those on as a separate Cascada task. A coordinated engine release is already required for `makeSharedIterable` and `NotFoundError`; no package publication or engine modification is performed here.

## Subsequent Claude review reconciliation (2026-11-06)

This is a reconciliation of the supplied findings, not another claim of a complete implementation audit.

- **Voice clearing fixed:** shared undefined-setting selection now omits cleared and conditional fields before native session setup, including absent instructions. A real OpenAI Live adapter over fake fetch covers inherited clearing and native rejection of a defined unsupported setting.
- **Plain-tool schema timing fixed:** the existing declaration reader checks the documented input field during metadata preparation, before a native ToolLoopAgent calls its model. Ordinary and injected execution reuse the same check; no extra schema parser or discovery cache was added.
- **Plain-tool diagnostic fixed:** the custom-field diagnostic takes precedence over native-value compatibility, avoiding an intersection of incompatible error strings. Missing positional documents/audio-format diagnostics still expose the generic rest-tuple error; their acceptance rules remain correct. Improving these messages is deferred rather than adding another callable-validation layer in this patch.
- **Incomplete image object retained:** native ImagePrompt requires `images` on an object prompt. The SDK and Casai both produce the reported TypeError for `{ text }`; this malformed native shape is not a supported fallback bundle. A preparer returning text uses configured media. Reranker's supported `{ query }` preparer fallback is a different protocol. No native workaround or malformed-call regression test was added.
- **Validation ownership fixed:** retired LLM options are checked by the completed LLMAgent and its named calls. Reusable fragments receive common checks; unrelated SDK-backed components forward unknown native settings. Coded components retain their finite setting contracts.
- **Documentation corrected:** transcript tool results contain only `text`, `segments`, `language` and `durationInSeconds`; ordinary results retain native metadata. The image table permits invocation field overrides on complete bundles. Renderer status, minimum SDK version and compile-time-only rejection of removed embedding aliases now match the implementation.

Retained the small simplifications: one undefined-settings helper, the shared context classifier and text-source fallback, common named-call parsing, structured-renderer metadata in component definitions, native-derived WebRTC result typing, native handling of the scalar embedding call's unused batch option, and removal of the duplicate pre-metadata cancellation check. The post-metadata cancellation check remains necessary.

The remaining architectural suggestions were inspected but not applied. Tool-result projections stay beside each native invocation; centralizing their small conditionals would add a projection callback protocol while preserving all owner-specific selection. Argument-role types serve different tasks (tuple omission, source recognition and application-context extraction); the shared runtime classification removes concrete duplication, but a wholesale type unification has no demonstrated failing supported call. `definition.keys` also distinguishes coded descriptor ownership, and Function's invocation-local `execute` slot holds its prepared value: both are internal conventions, not extra executions or mutations of configuration. Splitting them would add flags or a second prepared-value channel. Fragment prompt validation still needs the image source alternative to preserve current static compatibility; removing it or expanding it across the whole registry needs a separate inference evaluation.

The mutation runner is now available through `npm run test:component-mutations`. Historical test filenames and the full review archive were left in place; prior scoped verification statements are evidence for their recorded cases, not guarantees that later reviews cannot find defects. No new public API decision is required for this patch.
