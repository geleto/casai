# Future Features

Features recorded for later. Async call context and deadlines are assigned to Phase 5; broader telemetry features and other items remain directions rather than agreed APIs. The current plan is in [agents-design.md](agents-design.md).

- **Telemetry.** Cascada will publish telemetry on one global channel that all nested calls report to: model usage in tokens, timing, request counts, and the call tree.
- **Context channel.** Cascada's async call context passes an absolute end time and call ancestry implicitly from each component to its children. Concurrent calls have separate frames, not one mutable global stack. Signals are derived at SDK/cooperative boundaries, not required context state. See [abort.md](abort.md).
- **Async context tracking.** Develop this in Cascada together with telemetry, so both telemetry reporting and inherited state follow Script/Template calls, SDK tools, and ordinary asynchronous JavaScript, including components called by Function callbacks. This shared foundation is the upstream prerequisite for Phase 5; Casai must not build a parallel tracker. A Function implementation can query the current end time. Late-running work and returned streams retain their execution context.
- **Telemetry for any component call.** Read the telemetry of one call, including its usage, time, number of model requests, and call stack, for any component. Template, Script, and Function return plain values today, so this needs a form that leaves those values unchanged, such as a callback or separate metadata access alongside the agreed `.run()` method. Decide once telemetry exists.
- **`onUsage` on every component.** Report the tokens used by a call and everything it ran. LLMAgent already reports its own call's tokens through the SDK's `usage` fields and `onEnd` callbacks. Template, Script, and Function get `onUsage` once Cascada telemetry works.
- **Timeouts across nested calls (Phase 5).** A child uses the earlier of its parent's end time and its own timeout from entry. Once async call context exists, Function/Script/Template may race completion against that deadline before native engine abort is available. The wait can end while work continues, but nested components still inherit the deadline. Preserve native SDK cancellation in the meantime; see [Phase 5](agents-design.md#phase-5-async-call-context-and-deadlines) and [abort.md](abort.md).
- **Native engine interruption.** When Cascada supports abort and owned-work cleanup, connect them to the Phase 5 deadline to stop rendering as well as end the wait. This is a later enhancement, not the prerequisite for timeout races. Arbitrary JavaScript remains cooperative.
- **Progress for streaming tools.** A streaming Casai tool could report SDK preliminary tool results as cumulative snapshots, the text or elements so far, so chat UIs show tool progress. The final result stays the completed value.
- **Out-of-order streaming.** Delivering stream elements before earlier positions are ready; see [Phase 6](agents-design.md#phase-6-out-of-order-streaming).
- **Live VoiceSession.** Separate from Phase 3 `VoiceSessionSetup`: an audio stream in and session events out, for telephony or server-hosted agents; see [transcription and voice](agents-design.md#transcription-and-voice).
- **Coded components behind the SDK chat protocol.** A custom `LanguageModelV4` provider could let a Template, Script, or Function serve SDK UI helpers with real SDK results. Assess it when an application needs it.
- **Background jobs and resumable operations.** Long-running work needs explicit execution handles rather than state in shared configuration; see [shared infrastructure](agents-design.md#shared-infrastructure-and-capability-boundaries).
