## Independent A/B evaluation, 2026-11-18

### Content, dispatch and diagnostics

1. **High · Native preparation removes interior pauses.** Two 48 kHz mono PCM Matroska recordings contained identical samples. In one, the packet timestamps placed a one-second pause between two sections of sound. Native packet inspection measured a 2.000 s presentation, including the pause. Both the raw target and the copied PCM WAV sent the model exactly the same 48,000 nonzero samples as the uninterrupted 1.000 s control. Raw decoding discards frame timestamps, and copying packets into WAV discards gaps the container cannot represent. Place samples on their presentation timeline with bounded silence, or reject a discontinuity the selected route cannot preserve. Check the first sound after the gap and the actual output duration for both targets. [Native pipeline](../src/audio/native-pipeline.ts)
2. **High · Enclosing component debug logs expose private media configuration.** A synthetic header set only on a configured `.loadsAudio.asTool` was present in the arguments passed to `console.log` when a debug-enabled LLMAgent or Function registered that tool. Both log the enclosing config, which contains the tool and its config. The observation concerns logging, with no evidence of that header reaching the model. Log the component kind and operation at these sites. Passing the whole object gives structured loggers access to headers and resource URLs regardless of console display depth. [LLMAgent](../src/runtime/llm-agent.ts) · [Coded components](../src/runtime/coded-component.ts)
3. **High · Ordinary transcription bypasses MIME checks for supported representations.** The same Matroska/FLAC recording failed the positive-but-wrong WebM check as local bytes, then reached the SDK model as `audio/webm` as native base64 or a different realm's `Uint8Array`. A different realm's WAV `ArrayBuffer` also failed ordinary raw preparation while the local buffer succeeded. Check the native file representations through one bounded evidence path, use the SDK's realm-safe byte predicates where applicable, and retain native URL downloading. [Supplied audio](../src/audio/supplied.ts) · [SDK handoff](../src/audio/input.ts)
4. **High · Strong container evidence can be missed or mistaken for an exact MIME.** Ordinary raw transcription forwarded the headers and encoded payloads of real AIFF and Sun AU files as PCM. Node `.loadsAudio` did the same with a reusable headerless layout. Omitting the layout decoded both to the expected 96,000 PCM bytes. In the opposite direction, a correctly declared ID3-tagged AAC file was rejected although native transcription identified AAC, and a declared QuickTime PCM recording was sent as `audio/mp4`. An ID3 tag or generic `ftyp` box establishes less than a codec or exact MIME. Distinguish encoded routing evidence from an exact label, recognize strong AIFF/AU headers, and preserve weak MP3/ADTS prefixes as valid raw samples. Matching raw MIME also discards explicit layout parameters. The same 8,000-byte PCMU Blob declaring an 8 kHz rate was dispatched at both 8 and 16 kHz. [Evidence classifier](../src/audio/source-evidence.ts) · [Supplied audio](../src/audio/supplied.ts)
5. **High · Valid whitespace in base64 can change PCM samples.** A stream containing 120,000 PCM bytes produced identical resampled output as bytes, compact base64 and base64 wrapped with CRLF at 76 characters. Wrapping the same input with LF changed the output hash. Inserting one space caused `InvalidCharacterError`. The installed SDK decoder read all three whitespace forms as the original bytes. The wrapper splits each string every 32,768 characters and decodes each piece independently. Retain quartet alignment across bounded pieces of a single source chunk, counting significant characters. [Stream partitioning](../src/audio/pcm.ts) · [Worker decoding](../src/audio/pcm-stream.ts)
6. **Medium · Cancellation is lost while assembling completed audio.** Aborting on the first worker allocation after the SDK finished a translation still fulfilled the call with 2,097,152 bytes. Translation and speech collectors call the same signal-less concatenation helper, and the collected tool path also encodes base64 locally. Carry the invocation signal through these existing operations and check it before publishing the result. The native stream can complete successfully while this work is still outstanding. [Translation](../src/factories/Translator.ts) · [Speech](../src/factories/SpeechGenerator.ts) · [Audio workers](../src/audio.ts)
7. **Medium · Escaped file URL strings fail on Node.** The same Windows file opened by filesystem path and by `URL` object. Its `file:` URL string containing `%20` and `%23` failed with a native missing-file error. Only the object branch calls `fileURLToPath`. Apply that conversion to file URL strings too, preserving ordinary paths and signed network URL strings. [Native source handoff](../src/audio/native.ts)

### Required inputs and public types

8. **Medium · A finished tool can compile with no executable input/setting combination.** An empty-schema Transcriber with configured numeric samples, or a typed function preparer returning them, compiles without the required source rate and channels. Descriptor and injected execution then fail. A SpeechGenerator tool whose parsed `text` is a string array compiles with `outputFormat: 'mp3'`, although every such call is rejected. It also admits complete-only `maxRetries` for that streaming input. Apply the existing native request and PCM requirements to the known configured, prepared or parsed input of the finished tool. Arbitrary script output can keep its invocation-time check. [Factory admission](../src/factories/component-factory.ts) · [Transcriber](../src/factories/Transcriber.ts) · [SpeechGenerator](../src/factories/SpeechGenerator.ts)
9. **Medium · Ordinary call types and native target types admit guaranteed failures.** A raw Transcriber accepts numeric shorthand without a source layout and a named `Uint8Array | Float32Array` input with the same omission. A known numeric named call correctly fails to compile. The broad forwarding overload checks the whole allowed tuple, and the layout guard misses a numeric alternative in a mixed union. Loaded Transcriber/Translator also accept explicit companded targets and PCM targets without a rate, despite the native preparer requiring rate-bearing mono PCM16 output. Check the actual possible input at the call site and express the required rate and known format exclusions for loaded preparation. Preserve finite self-describing inputs, valid forwarding unions and native direct-stream formats. [Call signatures](../src/types/component.ts) · [PCM layout](../src/audio.ts) · [Native target](../src/audio/preparation.ts)
10. **Medium · A null image preparer result escapes the mandatory-input check.** An empty-schema `ImageGenerator.withScript.asTool` executing `return null` entered the SDK and failed on a null property access when images were absent. With valid configured images the model received `prompt: null`. Treat a nullish prepared text as absent before dispatch, keep image-only requests valid and preserve the SDK's handling of explicit native image bundles. [Image request assembly](../src/factories/ImageGenerator.ts)

### Smaller corrections and simplifications

- `Transcriber.asStream` reads an entire WAV Blob before reporting a missing `inputAudioFormat`. A counted Blob recorded one read and zero model calls. The format is already known to be missing before Casai starts media I/O. [Transcriber](../src/factories/Transcriber.ts)

Transfer the owned buffer directly and retain staged copying for caller-owned bytes. [Native source handoff](../src/audio/native.ts)
- Ordinary file transcription rejects a URL or base64 WAV if a reusable `sourceFormat` is present. The URL downloader received zero calls. A maintained test expects the URL rejection, while the public types admit the combination. Ignoring a headerless default on native file inputs would let one configured component accept either representation. [Supplied audio](../src/audio/supplied.ts) · [Existing expectation](../tests/SuppliedAudio.unit.test.ts)
- The Casai-owned `VoiceAgentBackend.executeTool` options skip the removed-control check. A call with `streaming: undefined` executed the tool. The other invocation helpers check settings before execution. Reuse that check on the options object while leaving tool arguments to their schema. [VoiceAgentBackend](../src/factories/VoiceAgentBackend.ts)

## Performance follow-ups

The [audio benchmark](audio-processing-benchmark.md) retains numerical comparisons and reproduction commands. Both scheduling and startup follow-ups are implemented; buffer trimming remains an unselected tradeoff:

- **PCM scheduling implemented:** finite workers have individual ordered queues within the existing logical-processor/four-worker cap. Resampling submits bounded 262144-sample jobs and yields its place between them; short operations progress even on one core. A shared iterator preserves one input-copy budget and limits prepared work. Other operations prepare input only in their queued turn. Streams remain independently owned; empty results bypass workers. Full offline/coverage, native, Node/browser and affected mutation checks pass. The measured short-result median is 0.7 ms versus 59.4 ms for a serialized control on this machine; this is not a latency guarantee.
- **Native reuse implemented:** one cleaned worker may remain idle for five seconds. Each invocation has its own port/resources/settings/signal; overlapping calls start separate workers. Failed/cancelled calls and excess/expired idle workers exit gracefully. The [measured comparison](audio-processing-benchmark.md#queue-and-native-startup-measurements-2026-11-17) shows a substantial startup reduction without changing the PCM queue.
- Prepared-file buffers grow geometrically. Native probes returned 9,678 / 72,078 / 1,440,078 bytes backed by 65,536 / 131,072 / 2,097,152 bytes. `maxBytes` caps capacity; the byte view excludes spare capacity from uploads. Capacity remains while bytes are reachable. An exact-size copy adds work and temporarily retains both allocations, increasing peak memory.

Buffer trimming is an unselected tradeoff, not scheduled work: a retained-capacity saving does not establish a net benefit after extra copying and peak memory. Measure sustained workloads before changing the selected scheduling policy or adding an obligatory output copy. Heavy work stays off the calling thread regardless of throughput. The four-worker cap is a budget, not a universal optimum.
