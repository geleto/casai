# Reviewing implementation contracts

Start from the public contract and the current implementation, independently of existing tests. A passing suite is evidence only for cases whose assertions would detect the relevant regression.

Cross generated context properties with JavaScript protocol behavior as well as prototype ownership. An own callable `then` makes an object a thenable: returning a helper-populated context from an async function can invoke a helper before the body runs. Follow the same value into another component and enumerate every asynchronous input/context return, not only assembly. Compare native safe-result envelopes with utilities that unwrap their value; wrapping after assimilation is too late. Test completion, unhandled rejection and first-statement entry independently, and compare with a native tool of the same name. Distinguish Casai-owned preparation from native execution/result limitations; a small internal result envelope can preserve names without introducing a blacklist. Separate explicit author serialization such as `JSON.stringify` from automatic library serialization before treating `toJSON` as the same defect.

Test two independently loaded Casai instances, not only duplicate schema-library installations. Cross component recognition, automatic public-default binding, stream collection and emitted types. A native-tool fallback must preserve Casai-specific guarantees before it counts as interoperability; compare configured and incoming defaults, not merely a context-free tool call. Distinguish compatible copies from arbitrary version compatibility and preserve the explicit descriptor-spread contract.

Separate host-to-component forwarding from the language engine's argument resolution before that call. A Casai fix cannot establish behavior at a boundary the engine has already consumed; retain a native engine control and exercise the Casai boundary independently. Likewise, native validator reuse is a simplification only if it preserves the intended public schema contract: compare runtime acceptance, native types, passthrough fields and all preparer/configuration consumers before changing tests to accept it.

When a dependency's runtime message schema omits fields from its public types, trace those fields into actual provider requests. Compare the SDK's validation-only prompt handling with parsed-copy consumers, and test approval and denial history through function, script and loaded preparers in generation and streaming. Public `.parse()` equivalence alone does not establish correct transport. Keep this distinction separate from application schemas whose parsed values must be used. During overload consolidation, inventory explicit `undefined` and union-valued optional parents even when other factories already require narrowing; record each newly rejected call form.

For protocol hazards, test failure as well as successful resolution: an async handler's rejected return can be ignored by the protocol consumer, leaving an unresolved outer call and an unhandled rejection. Use an isolated process to establish termination behavior without weakening the test runner's rejection policy. Cross raw binding/default selection with native context resolution before claiming SDK/injected equivalence. Across package copies, check error recognition separately from execution identity; compare the SDK's branded guards rather than assuming constructor equality. Keep dated verification evidence in the review ledger and link to it from status summaries instead of duplicating counts.

Audit manually reconstructed SDK settings against the installed native API and captured provider requests, including retiring factories. A setting can pass every Casai type/configuration test while the SDK ignores it. Before tightening validation for such a setting, establish that it still controls native behavior; remove obsolete surface and its supporting checks when appropriate instead of maintaining a parallel legacy contract.

For rejection-before-execution claims, count entry at the first statement of the implementation and assert that count independently. An identity assertion inside the body can itself produce the expected error after an unsafe entry, masking a missing boundary guard. Remove the actual guard in a controlled counterfactual and verify that the entry-count assertion fails. For runtime integrations, also prove that the compiler calls the intended runtime; passing through an old linked engine or testing the new kernel alone does not establish the handoff.

At integration boundaries, inspect the object passed to the native executor before the SDK discards unknown fields. Casai-owned configuration and outer tool metadata must stay out of model requests while native and future SDK settings pass through. Measure repeated validation against a native baseline, rather than inferring cost from source alone. Cross pre-aborted calls with invalid input and parser/preparer counters; distinguish Casai preparation from SDK-owned pre-executor parsing. Compare native marker values, not just marker presence. Capture expected error logs and assert their contents instead of silencing diagnostics globally. Keep snapshot bindings, deliberately mutable referenced state and application authorization separate when assessing caching or freezing.

Apply schema-selection checks to every schema channel, including `toolContextSchema`: conditional presence, a choice of parsers and one intrinsic union parser are distinct contracts. Follow raw context admission through explicit binding, required registry entries, reusable versus finished configurations and run overrides; proving application-input selection does not prove trusted-context selection. Pair each rejected selection with input valid under every possible selected parser.

Cross empty and nonempty public shapes with dependencies available only on some execution paths. A `Record<string, never>` output can make a missing field appear present when combined with a populated context (`never | T` collapses to `T`). Verify the exact callback field type and actually invoke the context-free path; a valid SDK execution alone cannot establish that the same implementation is safe on ordinary calls. Retain configured-dependency and native empty-object controls before changing index-signature handling.

Budget verification before execution: inspect previous timings and memory headroom, use focused checks while developing counterexamples, and run the full gate on the settled candidate. Keep compiler-heavy checks sequential. Record cold/warm cache state, wall time and compiler diagnostics when evaluating performance; a small type-cost fixture is not a full-project timing. Re-run only affected checks after corrections unless a new concern requires a broader pass. Mock provider behavior for local contracts and keep paid integration tests opt-in; see [test commands and performance](../tests/README.md).

Distinguish a single union schema from a choice between schema instances. `z.union([A, B])` deliberately accepts either branch; an `inputSchema: A | B` setting selects one parser, so a caller must satisfy every possible selected contract. Keep each alternative's public declarations, private bindings, defaults and parsed execution context together until its checks are complete. Cross privacy changes with missing required fields and incompatible primitive types, and check callback access to a field that is public/transformed in one alternative but retained privately in another. A global union of input types or public names loses these distinctions; the `Schema | undefined` case alone does not test them.

Follow those pairings into callback reconstruction and trusted binding. Removing an old callback with a non-distributive `Omit` can combine parent configurations before shared execution typing sees them. Include a positive where every actual selection produces the same field type but a false schema/default pairing would widen it. Also retain optional reads of configured dependencies absent in one branch and the completed output type of injected helpers; tighter caller checks must not degrade either. A new bound context must fit each selected implementation's own contract, not merely some member of the combined execution-context union. Preserve successful branches when collecting checks without letting their `unknown` result erase failures. Measure compiler cost on the same consumer, separating source-import checking from the new call workload; interrupted runs do not establish a regression or a pass.

When declaration discovery falls back to metadata, compare its type-level field names as well as admission: preprocessors can retain unknown raw input while still declaring public defaults, and output transforms can remove those defaults. Configuration ownership checks must include message arrays and getter evaluation time alongside map entries and intentionally shared nested resources. Trace diagnostic sinks separately from model/UI transports: native default logging can retain private error causes even when published summaries are safe. Check browser-facing helpers against insecure-context API availability and prefer the SDK's existing implementation. Inspect a fresh dependency tree when changing compatible ranges; declaration success alone does not establish runtime compatibility.

Cross schema capability with its consumers: a schema that validates locally may lack declarations needed by private bindings, registered helpers or tool projection. Compare native conversion failures with Casai's configuration diagnostics, preserving causes and a metadata-backed valid neighbor. Test map ownership by replacing entries in the author's original `context`, `tools`, `toolsContext` and `filters`, across standalone and one-sided inheritance, then compare ordinary and SDK calls; separately mutate a nested resource to verify that intentional sharing survives. Dispatch must inspect effective invocation settings, including untyped run-only registries. Test renamed configuration keys through JavaScript and Cascada as well as compiler rejection. For package checks, install the consumer's compiler explicitly instead of accidentally relying on a compiler shipped as a runtime dependency; verify the default lint/check commands themselves after changing their resource settings.

For schema integrations, vary both the protocol and the concrete implementation: Zod 4 Classic/Mini and SDK/Standard schemas, separate physical package installations, and distinct module instances. Constructor identity is not a schema protocol. Cross these with input/default discovery, output-name reservations, object-preserving wrappers, preprocessors/lazy schemas, unions/intersections with opaque siblings, non-JSON local fields, and actual parsing. Use non-JSON fields inside every supported structural form, not only plain objects. Separately check local declaration capability and model-default projection at factory, binding, registry and run boundaries. Test output declarations independently of input declarations and opaque transforms. Include explicit rejection of unsupported versions without restricting native third-party tools. Record native type erasure explicitly instead of claiming a runtime/type equivalence the schema library cannot express.

Every security case counted as implementation evidence must reach production factories or the actual shared enforcement owner. Prototype comparisons and native characterizations have different evidential roles. Before retiring a prototype, map its invariants to production tests, port unique lifecycle/error cases, retain useful independent native controls, and remove obsolete implementations and checkers from normal gates. Mutate discovery as well as collision checks: a perfect final guard cannot reject names that were never reserved. Include real generation/streaming, bare/bound tools, renderer forwarding, invalid neighbors, and a subsequent request when claiming transport protection.

When changing error classes, classify the failed contract rather than the time of failure: lazy schema capability failures remain configuration errors, while parsed inputs, outputs and stream elements are validation failures. Trace shared validators through factory configuration and invocation overrides, preserve native SDK/Cascada ownership and safe cause chains, and test `instanceof` recognition and distinction between error classes. Update public export/type assertions, consumer catches, documentation and mutation anchors together.

When reviewing identification mechanisms, distinguish runtime tags from standard JavaScript protocols and erased type-only constraints. Prefer existing data and callable capabilities when they express the required distinction; replacing a symbol tag with a string tag alone is not a simplification. Check unannotated native objects as well as constructed and processed Casai values, and preserve reuse of native objects that own subscriptions or lifecycle state.

When auditing `any` and `unknown`, trace public callback/helper types separately from permissive inference constraints and erased runtime boundaries. Preserve known schema output types rather than equating them with producer inputs, and pair required-schema checks with optional/no-schema controls. Use exact type equality and invalid-call assertions so accidental `any` cannot satisfy the proof. Prefer existing native schema/callback contracts and specialize only parameters that affect the exposed result.

For dependency-type ownership, inventory all exported and internal type families, including mode-specific request/result variants, runtime validators, executor tuples and minimal implementation views. Derive native fields from installed public contracts, and record why each retained adaptation differs. Compare full native member sets, not only selected properties. Probe native validator acceptance and parsed values before replacing a copied schema; distinguish validation-only consumers from consumers that use the parsed value. Preserve explicit-undefined and readonly authoring contracts, and test concrete schema intersections and never-returning executors before substituting generic inference helpers.

Extend reuse reviews to the dependency's actual public runtime exports. A similar helper name is insufficient: compare ownership, eagerness, cancellation, error propagation, identity and presence semantics. Exercise a native replacement as a counterfactual against the local contract before recommending it. Do not deep-import an internal helper or add a wrapper that restores more behavior than it removes. Distinguish a safe helper substitution from adopting another execution facade with different defaults or an intentionally future API.

## Establish the surface

Cross valid output-mode transitions with explicit removal of inherited mode-specific fields; rejecting removal of a still-required schema does not establish that clearing an obsolete schema or enum works. Check optional schema removal on Script as well as Function under both consumer optional-property modes. For function prompts, pair each whole-configuration branch's parser with its own callback and use raw input accepted by every branch; compare ordinary Function, inherited prompt configurations and direct child unions separately. A branchwise compatibility fix need not solve independent inference-slot rejection, and a successful union member must never erase a failing one.

When allowing mode-specific settings to be cleared, test annotated streaming configs whose unsupported enum slot is explicitly undefined, and carry cleared metadata into a later mode that supports it again. Keep constructor-only clearing fields out of run-setting completion. Derive required fields per complete configuration alternative before collecting missing keys; selecting the keys of a combined union can hide one branch's required schema.

After consolidating validation, reassess both diagnostic and guard duplication. Intersecting two different literal error messages can reduce a useful diagnostic to `never`. A surviving guard-removal mutation can indicate overlapping enforcement rather than missing rejection: test removal against the complete consumers, then keep one owner and mutate that shared boundary without discarding the original invalid cases.

For inference-constraint simplification, distinguish the configuration value contract from the provisional shape used to infer it. Trace every child and parent consumer before folding wrappers into an existing type. Centralize repeated compositions while preserving `Partial` placement, intersections, overload order and post-inference parent checks. Probe removal of each layer against valid calls and invalid neighbors; compare contextual editor types, emitted consumers and compiler instantiations on the same workload before calling the result equivalent.

When replacing a type-only inference marker with structural detection, test empty arguments, values annotated only as `object`, optional implementations, inherited dependencies and nested SDK callback arrays. A candidate can preserve callback inference while silently skipping real validation. Test conditional rest-parameter and defaulted-generic alternatives against valid-call arity as well as diagnostic wording, and do not count fewer instantiations as an improvement when rejection checks have disappeared.

Reassess older generic parameters after introducing independent callback/schema inference. A parameter used only to specialize a family constraint may duplicate a newer inference source; compare replacing it with its broad contract while retaining exact validation of the actual configuration. Check standalone tool selectors, literal enum callbacks and malformed schema values as well as inherited callbacks. A passing barrier-removal experiment does not establish a simplification if it substantially increases compiler work.

Check literal preservation and mutability before removing an enum element parameter: a callback array parameter can preserve string checking while widening every literal, and a const parameter can change a mutable array into a readonly tuple. When replacing an inferred final-config parameter with a derived merge, explicitly preserve its constraint on the actual merged values, including raw-parent schemas. Compare ambiguous output fields with complete configuration alternatives before replacing conditional return types with a native result alias. Reassess inherited-setting checks and return-inference barriers in the new structure rather than copying them from another factory.

When extending a factory simplification, compare whole families before extracting shared types: prompt/source capabilities, synchronous versus prepared streaming, native partial/element results and callable versus descriptor inputs remain distinct. Keep factory signatures local; share their repeated configuration, callback and validation rules. A required callback's presence belongs with its shared compatibility check. Test return annotations as well as arguments: they can infer a nonexistent parent or erase callback-inferred fields. Locate inference barriers using correlated schema/default alternatives and private registry bindings, not just standalone annotated calls; a barrier on a nested config or parent can alter downstream conditional-type behavior even when direct binding still rejects the invalid case. Explicitly erased runtime matrices do not replace uncast compiler consumers.

Cross explicit schema removal with a changed output mode under exact-optional emitted consumers. An overly narrow inference shape can discard the actual child and retain a parent's schema before final validation sees it; inspect the inferred `.config`, not just the diagnostic. Keep ordinary optional schema fields separate from required tool fields in final shapes. Exact-optional mutation fixtures must emit fresh declarations from their own source snapshot rather than relying on a previous root build.

Name helpers by their actual role: inferred definitions, callback contracts and validation of incomplete fragments are different concepts. Before adding an alias for readability, look for an existing composition that other factories reconstruct, and share it without moving inference barriers or changing union distribution.

When reorganizing type ownership, trace consumers before choosing module boundaries. Keep schema inspection independent of component policy, distinguish caller input from parsed execution context, and place results, configuration projections and reusable utilities with their existing owners. Preserve required type recursion without adding runtime imports or a forwarding barrel. Move mutation targets and their type dependencies together: a missing import must never count as evidence that a guard mutation was detected. Compare emitted runtime and public source/declaration/editor behavior after the move.

Inventory the whole types directory, not only the file being split. Check native-derived aliases, type-only re-exports, runtime constants/validators and exports referenced only by compiler fixtures. A single external consumer does not imply moving a type when it belongs to a cohesive family with shared private helpers; move implementation-only views and final factory signatures to their implementations. Keep an explicit owner map and distinguish general primitives from domain policy. Preserve public export names while eliminating internal forwarding aliases.

For factory performance, measure imports alone and multiple sizes of the same component workload against the immediately preceding source, not only an old aggregate budget. Report incremental instantiations separately from total imports, compiler time and memory; a cold aggregate reduction can hide growth per component. Test constraint reductions against native option types, public completion, both optional modes and guard mutations. Keep unresolved increases explicit instead of calling a permissive ceiling a fix. For output-mode checks, distinguish reusable fragments from completed components, inherited values from explicit clearing, and SDK validator rules from values its public entry point silently omits before validation; assert rejection before preparer/provider effects.

Keep factory-specific signatures beside their implementation; shared configuration types belong in the types layer. When simplifying a factory argument, review its complete admission, inference and validation contract rather than hiding a broad capture constraint behind an alias. Share repeated signature definitions where call forms differ only by parent presence, while retaining their arity, parent validation and processed-versus-inherited result types. Mutate the capture constraint itself: a supported-family constraint can let provisional inference conceal invalid supplied keys.

Before attributing a failed constraint substitution to its placement, vary object admission independently from the all-optional family shape and provisional validation. Test `object & Shape` as well as `Shape`; an optional structural shape alone need not produce the intended inference. Separately move schema/context inference sources and already-inferred parent checks, since those operations can lose callback inference or exceed compiler depth even when moving the child family constraint succeeds.

For an already-inferred parent, test `NoInfer` around the family bound in the type-parameter constraint before concluding that the check must stay on the argument. A broad parent bound can otherwise drive recursive inference through the child's generic settings. Reduce depth failures to their actual triggering expression: inheriting a callback-bearing loader is different from inheriting an empty loader configuration. Keep new diagnostic probes separate from the established contract until the unmodified baseline confirms their expected types.

When collapsing overloads into one factory type, preserve the distinction between an absent parent and a supplied empty parent. Test empty and one-element argument tuples, plus a tuple union whose parent might be absent: accepting that union while returning guaranteed inherited fields is unsound. Infer presence from the actual parent type only when the rest tuple and result use the same condition. Reassess existing mutations after changing the inference structure; an old compiler-depth failure may disappear while the barrier still reduces compiler work.

Also test contextual return annotations and nested factory calls when a type parameter represents argument presence. An expected `ConfigProvider` result must not infer a parent that was never supplied. Block inference from the returned parent contribution while retaining ordinary argument inference, and pair valid annotated results with checks that expected types cannot invent inherited fields.

For historical signature comparisons, distinguish replaying old overloads against current dependencies from running the complete historical environment. Compare explicit type-argument order and arity as well as inferred calls. Trace the actual merge type and runtime policy, including retained map fields, concatenated messages, optional children and union alternatives. Check empty children and manually supplied parent providers; structural parent admission, exact merged-family compatibility and finished-component readiness are distinct guarantees. Mutate merged validation independently of the parent-property check.

For inline-type cleanup, inventory runtime annotations and supporting typedefs as well as factory constraints. A local alias can reveal a shared domain contract that other modules still spell out; keep prompt values distinct from prompt callbacks, and configured tool entries distinct from executable registries. Repetition alone does not justify naming simple primitive constraints.

Inventory exports, factory modifiers, callable forms, inherited configuration, `.run()`, tool adapters, result getters, callbacks, and downstream Script/Template consumers. Include descriptor copies, symbol-keyed bindings and idle stream views after a task boundary. Check mixed positional/keyword calls for rejection rather than silent argument loss. Separate implemented requirements from explicitly deferred work and accepted native limitations. Reconcile current status and links with existing files; date historical evidence instead of labelling it current. Check runtime behavior and public types separately. Inspect assertions in LLM-backed test files too: local configuration, loader, and error behavior belongs in mock-only coverage so validating it never requires a paid model call.

For each boundary, record its inputs, owner, output, failure behavior, and authoritative evidence. Follow a value through configuration, argument resolution, preparation, SDK execution, augmentation, consumption, tool conversion, and a subsequent conversation turn. Include empty, missing, optional, union-valued, transformed, and asynchronous inputs.

For each inferred guarantee, test the branch where its enforcing value or parameter is absent. Distinguish a preliminary shape used for inference from the final proof of completeness: accepting `{}` against the former does not justify a zero-argument call, and an optional-parameter intersection cannot reject an omitted parameter. Cross incomplete union-valued defaults with shorthand, explicit empty arguments and `.run()` on the same component. For conditional schemas, separately execute present and absent branches and check both callback input and returned output types through their downstream consumers; an optional declared contract and a required property holding `Schema | undefined` are different cases.

For a conditional input schema, also vary a configured field declared by its present branch. Removing the schema changes that field from a public default to a private binding. A correction must represent both accepted-call contracts as well as both raw/parsed execution contexts; changing only the body field types is insufficient.

State the guarantee across alternatives before choosing a conditional-type operation. A call must work for every possible argument/configuration state; one complete schema branch must accept each effective input; a result must include every possible parsed outcome. Vary the position of alternatives independently: a field value, whole argument, schema, whole configuration, inherited fragment and registry entry. `{ schema: S | undefined }` does not exercise the same extraction as `{ schema: S } | {}`. Audit `keyof`, non-distributive `Omit`, setting accessors and whole-union predicates at each step. Mix closed and open/catchall branches in one discriminated schema; a global open/closed flag must not weaken a closed branch. Pair each case with valid neighbors and actual downstream operations, and compare suspected restrictions with explicit contract exceptions before reporting them as bugs.

Repeat that audit for settings not used in application/result inference. A branch-only tool registry must retain its required context, and a branch-only inherited callback must still match a replaced schema. Pair a forbidden setting present in one alternative with a valid absent-setting alternative: filtering a union to its valid members and testing for a nonempty result proves only that some configuration is valid. Final factory admission must reject any invalid possible configuration. Compare the same conditional settings with native SDK construction, then exercise the selected branch through callbacks and execution. For streaming failures, inspect error parts as well as completion promises; native partial steps can resolve even when execution emits an error.

When fixing alternative admission, preserve each complete branch before deriving its expected contract. Collect failures with `never` for a successful branch; a distributed `unknown` success can erase other branches' errors. Test positive correlations as well as rejection: tools paired with their context, callbacks paired with their schema, and mode-specific properties paired with object/enum output. Compare new restrictions with the pre-fix implementation before accepting them. A stricter key check must not mistake legitimate branch-specific settings for unknown properties.

Keep mutation evidence specific to its layer. Focused shared-owner mutations can isolate expensive type predicates, but they complement rather than replace exported-factory negatives, valid neighbors, source/declaration compilation and editor checks. Distinguish these from mutations tested through actual public consumers. Timeouts and interrupted checks are incomplete evidence; compare compiler cost on the same workload and avoid treating concurrent wall-clock timings as a regression measurement.

Run memory-heavy compiler, language-service and typed-lint checks sequentially when the workspace is constrained. If lint stalls, isolate its file and rule and compare standalone compiler checks before attributing the cost to the public API. Runtime-only fixtures may explicitly erase types at an annotated `unknown` boundary before asserting a small callable shape; keep those separate from uncast public compiler consumers. A direct double assertion on a generic factory can make assertion lint expand its entire API; isolate the exact rule/expression before changing production types or weakening checks. If lint needs smaller batches, enumerate the same complete file set with unchanged configuration and rules. Record successful batches separately from interrupted monolithic attempts; a resource limit is neither a passing check nor evidence of a production defect.

For asynchronous verification processes, report success only after the full assertion sequence completes. An unresolved promise alone does not keep Node alive; a zero process exit is insufficient if expected completion markers are missing. Keep process cleanup independent from assertion success, drain child output before checking its exit, and verify a forced assertion failure produces a nonzero status. Interrupted language-server sessions are not completed editor checks.

When changing generic inference, compare explicitly conditional properties with optional annotations and conditional spreads. Test the final exported factory, not just its internal signature alias: attaching modifiers with `Object.assign` or an object shorthand can accidentally expose the implementation signature. When moving a generic constraint after inference to avoid compiler-depth limits, retain its rejection of every invalid alternative; checking only the merged result can erase an invalid parent branch. Verify valid callbacks, inherited replacements, unknown-setting rejection, editor completion, emitted declarations and measured compiler cost before accepting an inference refactor.

Use the confirmed parent argument for whole configuration alternatives; an unsupported child spread is not a reason to add another initialization pattern. Separate that factory-inference question from call-argument unions. Cross whole arguments with branch-only catchall values, optional `undefined`, private names and disjoint valid extras. A required-key check can reject a valid union, while a wider signature can infer only its common fields and miss an invalid branch. Test the same calls through unions of required and optional components: tuple capture that fixes an individual call can accidentally admit zero arguments. The user permits requiring narrowing for different component alternatives when it simplifies the implementation; preserve valid calls after narrowing and reject every unsafe combined call. Test two optional components as well as mixed required/optional ones, and retain contextual function-valued input inference.

Also vary the entire invocation-settings envelope: `{ maxOutputTokens: number } | { context: ... }` is different from a present `context` whose value is a union. A common-key test must not skip validation of a context present in only one settings alternative. Retain valid absent-context/defaulted-input neighbors and verify rejection before rendering or model dispatch. Treat compiler inference experiments that weaken component-union calls as failed experiments, not fixes; discuss a supported-call contract change before integration.

Separate a union of components from one component created with a union of complete configurations. Renderer argument tuples must not distribute configurations before deciding whether input may be omitted: an optional branch can otherwise introduce a zero-argument overload that skips the complete-input guard. Check omitted arguments, explicit source, named calls and valid fully configured neighbors across coded and model renderers, including parent configuration alternatives.

Cross provided-key inference with mapped/intersection execution contexts and ordinary indexed interfaces. An uninferred key slot must not turn a supplied object into empty input, and a broad index signature must not erase an explicitly named private field. Pair valid body-to-child forwarding with a named-private-field rejection and a real model forwarding attempt. Keep contextual callback/default cases too: dropping provided-key inference can restore the mapped-input case while rejecting an omitted configured field in a callback literal.

For helper substitution, compare accepted raw calls, configured omissions, private names and completed results separately from SDK descriptor compatibility. Generic signature assignability alone can accept incompatible helpers. If a type-only structural contract is used, test open-to-closed replacement, newly constrained optional extras, mixed unions whose openness changes branches, conditional defaults and selected parsers. Retain compatible widening, new callbacks and ordinary native tools. Mutate each distinct obligation; measure a registry workload as well as ordinary calls. No type-only proof establishes runtime validation or private-data enforcement.

Inventory schema-dependent native properties from the installed SDK, including properties inherited from a shared configuration base. Check contextual inference, explicitly annotated callbacks and inherited callback reuse after a schema change. Compare exported callback aliases against the actual callable SDK request: older aliases can remain exported with different event or return contracts. A callback omitted from a hand-written property selection can evade compatibility checks; successful runtime copying does not prove correct inference. Compare a valid inline callback with its native equivalent, and require each claimed unsafe call to compile without unrelated implicit-any errors or casts.

For a whole-phase review, maintain an evidence ledger rather than treating this document's checklist as completion evidence. Inventory in both directions: requirements to runtime/type consumers, and exports/modifiers/internal consumers back to requirements. Each row must distinguish demonstrated behavior, a specified but unimplemented obligation, an accepted native limitation, and an unresolved design gate. Record the actual assertions and native comparison, not just a test-file name or passing count. Include an explicit second pass from consumers after corrections, with remaining gates visible; do not label that pass clean while important gates remain. See the [Phase 2 ledger](phase2-review.md) for an example.

## Run a change-impact pass

For a phase that changes public behavior, use a finite change ledger before reviewing implementation details. A surface inventory says where to look; it does not establish that each consumer follows the new contract.

1. **List behavior deltas, not just features.** For each change, write an old call, its new outcome, and a valid neighboring call. Include defaults, names, callback arguments, error ownership, result types and consumption. Mark behavior deliberately retained, such as native tools' `contextSchema` and retiring factories' existing call forms.
2. **Find consumers independently of the plan.** Search exports, construction/call sites, inherited fragments, README code blocks, runtime assertions and compiler positives/negatives. Use syntax-aware scans where they help distinguish configuration from native SDK properties. Treat scans as candidate inventories, not proofs of completeness. Assign each hit to a change, an intentional native/legacy example, or a dated counterexample; do not leave unexplained hits or blindly rename matching text.
3. **Record an actionable row.** Each delta needs its owning slice, concrete runtime and type consumers, example/migration action, and evidence status: current baseline, demonstrated candidate, implementation acceptance test, or unresolved decision. A test name or passing count does not close a row. Current-behavior tests change with production; target documentation may change now.
4. **Cross boundaries by risk.** Prioritize new behavior plus inheritance/overrides plus a different consumer. For every validation owner, separately inject input, trusted-context, output and lazy-element failure. Check both Casai and plain native registry entries, SDK and coded callers, and actual downstream error conversion. Success-path equivalence does not imply failure-path equivalence.
5. **Trace confidentiality through failure transport.** A private sentinel must stay absent from normalized next-provider requests and model/UI error text, as well as successful arguments. Assert a next request actually exists when testing continuation. `JSON.stringify(Error)` can omit its message and produce a false negative; inspect the message and the real SDK transport. Native validation before executor entry can stop a run, while the same error inside an outer tool can become model-visible output. Retain native causes for trusted diagnostics without copying private values into Casai-owned public summaries; do not invent a universal error scrubber.
6. **Challenge the evidence.** Pair each negative case with a valid neighbor and independently remove important guards or adapters. Run actual callable source/emitted types and example checks; type algebra and runtime-erased fixtures answer different questions. Compare native behavior before classifying a difference as a defect. For lazy shared preparation, identify every first consumer: metadata, argument validation, approval revalidation and injected invocation can run in different orders. Test failed setup with zero provider requests as well as a successful next request; inspect stream parts and UI chunks even when history/completion promises reject. An error type shared by two paths does not prove that both paths have the same boundary.
7. **Close from consumers back to changes.** After corrections, revisit every ledger row, not just the new failing test. State which gates were checked and which remain assigned to implementation. Begin independent slices once their contract is settled; do not claim whole-phase completion while production acceptance rows remain open. No review can guarantee zero defects, but an unassigned consumer or unchecked boundary must be visible.

Audit the primitives that enforce each invariant across consumers, not only each feature's happy path. For name-indexed maps, enumerate dynamic reads, writes and presence tests in defaults, registries, context selection, binding checks and metadata projection. Compare empty maps and ordinary names with `toString`, `constructor` and `__proto__`, including own `undefined` and valid own overrides. Assignment can invoke an inherited setter; a TypeScript assignability test can count inherited Object members as present even when `keyof` does not. Pair runtime presence with declared-key typing and mutate each correction independently. These are small map operations, not grounds for a general key blacklist or changing native parser behavior. The [dictionary-boundary pass](phase2-review.md#dictionary-boundary-and-whole-surface-pass-2026-10-19) demonstrates why an input-payload prototype test alone misses them.

See the [Phase 2 consumer-first pass](phase2-review.md#consumer-first-review-2026-10-19) for the ledger and failure-owner matrix produced by this method, and the [binding continuation follow-up](phase2-review.md#binding-continuation-and-call-envelope-follow-up-2026-10-19) for the first-consumer and zero-request cases that pass initially missed. Check every recommended fix against its actual authority: an unknown-key settings guard does not prevent a recognized source key from executing, and SDK-owned settings must not silently acquire a Casai whitelist.

## Review a pass

1. Challenge the contract before fixing a mismatch. Prefer the native SDK or Cascada contract when it serves the intended behavior with less machinery. Inspect the installed SDK Agent/tool types and `ToolLoopAgent`, following delegation into the owning execution, schema, approval, and history modules before proposing a parallel Casai mechanism. Read native tests when available and use focused native probes; see the [native SDK reference](plan.md#native-sdk-reference). Compare suspected inherited limitations directly with the native API, including Agent where relevant. Do not add machinery for deliberately invalid or very unlikely developer code unless the correction is simple or the boundary is exploitable by an end user/model.
2. Read every applicable dispatch path. Compare sibling factories and modifiers, but do not require identical envelopes or timing when their native capabilities differ. Exercise installed provider adapters with representative HTTP/SSE fixtures and fake fetch, alongside SDK model mocks. Compare normalized and raw finish reasons, content blocks, provider tools, and refusals; mocks alone cannot establish what an adapter exposes. An invalid fixture leaves that API unverified.
3. Exercise interactions, not only isolated settings: inheritance plus overrides; preparation plus cancellation or caller mutation; retries plus transforms; tool work plus finish reasons; result consumers plus early closure, failures, and repeated access; overall versus final-step finish reasons changed independently by SDK transforms; parsed values plus downstream tool/history use. Inject faults before the first provider stream is returned, inside a returned stream, and during continuation setup, across invocation modes, output kinds, and consumer orders. Compare error identity and causes as well as success/failure; these boundaries can use different native error paths.
4. Check equivalence and ownership properties. One invocation executes once; successful final output matches the same execution's native parsed output; native fields/callbacks remain native, including callback receivers and capture timing; shared configuration and caller arrays remain intact; history follows native message availability and records the same input block that was executed. Mutate borrowed request arrays and top-level settings after entry, including on literal SDK paths rather than only through renderers. Respect the documented consumption contract for custom iterators and object streams.
5. Check exact public inference with the supported consumer compiler (TS7) against source and built declarations, in both optional-property modes. Pair rejected cases with valid neighbors. Include optional settings, unions with branch-only keys, inherited alternatives, custom output kinds, and SDK tool-map consumers. Casts cannot prove a public type contract. If a runtime test batches heterogeneous components whose signatures require narrowing, keep its explicit type erasure local to that matrix and retain concrete, uncast compiler positives and negatives; an uncallable component union can make an expected rejection vacuous.
6. Run `npm run test:coverage` and inspect uncovered branches against the changed runtime paths. Record retained native-precondition guards explicitly; do not add coverage exclusions or contrived invalid calls just to reach 100%. Check declaration-only changes with `test:types`. For important guards or proposed removals, identify a meaningful counterexample and run a targeted mutation. Verify the exact owner changed after refactors; first-match text replacement can target a sibling path. Distinguish equivalent survivors from missing coverage and native behavior. Do not retain redundant implementation branches merely to satisfy a mutation score. Restore mutated files byte-for-byte before normal verification.
7. Trace each finding to a reproducible case, intended contract, user-visible consequence, native comparison, and resolution. Add focused regression coverage for confirmed bugs. Record accepted limitations and unresolved decisions explicitly; do not silently weaken the requirement.

## Improve the next pass

For a focused security pass, construct an attack-path ledger independently of the feature checklist. For each attacker-controlled source, identify the transformations and forwarding hops, the private facts available at each boundary, and the first execution or disclosure sink. Separate binding replacement, mutation, confidentiality and executable-source/control injection. A guard protects a path only if its facts are available before the relevant sink; preparation-time declarations and actual execution-time context are distinct. Cross bare context with unknown declarations and actual private fields, and cross nested input/output failures with next-provider and UI publication. Check sibling/owner isolation as well as replacement. Every important guard needs a counterfactual mutation that reaches its sink, with a valid neighbor; record production-only paths as gates instead of treating fixture coverage as integration evidence.

Assess proposed protective mechanisms against a concrete attack, their enforcement owner, what remains unprotected, compatibility cost, and an independent failure-detecting test. Separate required enforcement from optional hardening and application authorization; more guards are not inherently safer. Curated loops and mutation tests are not evidence of broad generated schema/path coverage. Generated cases need a bounded grammar, reproducible inputs/seeds and an independent oracle, with unsupported cases and accepted authoring limitations labeled separately. Revisit the native ownership contract when changing purity/state assumptions: ordering within one execution may impose stricter identity-sharing rules than merely offering no global lock. A new wrapper or shallow copy does not establish isolation of nested state. Distinguish an independent review of the integrated implementation from another pass over the author's fixture.

Verify whether an upstream restriction is enforced or is a host obligation, and distinguish overlapping executions from sequential reuse. In generated cases, native parsing determines stripped/retained values but an independently declared test partition determines private ownership. Do not derive the expected protected-name set from the helper under test. Context parsing may itself materialize a prototype-named declared field, while application parsing may strip a prototype-shaped extra; neither should be misclassified as a Casai substitution. When a guard-removal mutation survives, check whether another guard still enforces the same path. Test the actual semantic exemption rather than claiming every redundant check is independently necessary.

For native security settings, test the lifecycle they actually govern: provider advertisement, fresh response parsing, local execution, approved-history continuation and trusted coded forwarding can use different registries/policies. A native signature can authenticate public input without binding a tenant, session, implementation or replay identity. Cross valid signed history with changed private context and current denial/removal policy. Follow parsing upstream of a wider executor registry before claiming a bypass. Compare native and adapted behavior, then classify a concrete adapter defect separately from a native limitation or application authorization obligation. During integration, connect every real consumer with these checks in its owning slice; a final independent audit cannot replace enforcement implemented and verified along the way.

Security probes must compile through the intended public APIs where their calls are valid. An unsafe-input cast can exercise runtime rejection, but do not hide an unrelated inference failure behind that cast. Cross output constraints with context-dependent callback inference and registered alternatives; check positive producer inference as well as negative return checks. Generic return checks can run before callback inference, and non-distributive helper inference can destroy correlations between alternative tools. These are type-contract findings, not evidence of a runtime security bypass.

Test partial knowledge separately from complete knowledge and complete opacity. A classifier that cannot describe one branch must not erase security facts already established by another. For each discovery result, distinguish "these names are known" from "all names are known" and check what each consumer actually needs. Cross supported/opaque alternatives in both orders, active/inactive branches, absent optional values, wrappers and actual downstream execution. Input-default partitioning and private-name reservation need different certainty; do not apply an all-or-nothing capability check to both. A characterization test can preserve a flawed assumption, so verify its expected outcome against the invariant rather than treating its existence as evidence. See the [mixed-context-union finding](phase2-review.md#partial-context-knowledge-review-2026-10-20).

For every conditional runtime capability, enumerate all triggers and compare them with factory admission. Default selection, private reservations, executable registries and binding can independently require the same operation; checking only the first trigger in types leaves valid-looking components that cannot run. Include inherited and removed entries, wrappers, opaque alternatives, and metadata-backed valid neighbors. Give each independent trigger its own mutation instead of relying on a broad failing schema test.

Verify that each final factory actually applies shared admission and call guards; the existence of a shared helper or a passing coded-factory test does not establish its use by LLM renderers and tool forms. Pass the same union-valued argument through shorthand, coded run and LLM run, with a forbidden/private key in only one alternative. Distinguish all possible supplied keys from keys common to every alternative, without weakening complete-input checks. Likewise, cross schema alternatives that change delivery: a stream schema or a scalar schema needs separate ordinary-producer and collected-tool result types. Follow those alternatives into injected helpers and descriptor callbacks, and execute an operation the inferred type permits. Concrete-kind and schema-present/absent tests alone do not cover these cases.

Pair branch-only forbidden names with branch-only permitted extras and disjoint catchall keys. Inferring every possible key must not require every key in every alternative. Before relaxing that restriction, check wrong catchall values and explicit undefined in a branch that can be structurally hidden by another alternative. An inferred generic can narrow away supplied value information even when a separate generic retains its key; a partial key map alone does not establish soundness. Keep known-restriction characterization tests distinct from accepted API behavior.

For helper replacement, compare the calls accepted before and after replacement, not the source of an omission guarantee. A schema default can preserve an omission previously supplied by configuration. The reverse replacement can still be invalid because an optional schema accepts explicit `undefined` while a configured required field does not. Cross these directions with selected schemas and keep raw-value, omission, private-name and result obligations separate.

Cross a context transform with both valid and incompatible replacements, and include a tool without a context schema. Use the SDK's inferred descriptor context instead of reconstructing it from a producer-facing settings map.

Distinguish optional positional arguments from optional properties inside their objects. In exact-optional mode, an optional tuple member does not automatically accept explicit `undefined`. Test omission and explicit `undefined` on every supported source/history position, while retaining rejection of missing required input and invalid present object fields. Helper omission guarantees must also account for invalid configured values and fields required by any input-union branch.
