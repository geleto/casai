# Reviewing implementation contracts

Start from the public contract and the current implementation, independently of existing tests. A passing suite is evidence only for cases whose assertions would detect the relevant regression.

For resource-loading integrations, inspect the concrete driver before accepting a stream return type as incremental I/O. Cross text/binary and complete/streaming reads with legacy loaders, cache/pending-request sharing, ordered/raced acquisition and cleanup of late losers. Test multibyte decoding across every chunk boundary and distinguish loader backpressure from consumer replay/concurrency. Compare native file/URL input with byte-stream adaptation: seeking, media-manifest resolution, authentication/access and format probing may change. Keep generic resource loading separate from media protocol/session handling, and prefer native delegation over recreating either runtime.

For media auto-detection, distinguish the native opener from convenience probes and SDK/provider file handling. Read probe error/confidence/buffer-padding behavior, stream-info decoding and native URI classification before promising transparent adapters, header-only reads or zero video decoding. Cross omitted/forced formats with every effective preparation option, custom download ownership, raw/container inputs, filename/MIME hints, file-URL escaping, Windows paths and opaque protocols. Keep the requested processing pipeline separate from incidental native inspection. Test late/partial probe data, read failures and cancellation without inventing a detector or recovery engine, and document the finite buffering required by the selected SDK operation. Future guides must explain auto-detection and its limits, not merely list the format property.

For authenticated sources, trace every request owner: source download, model execution, redirects, range/reconnect requests, child manifests/segments and keys. A shared option name does not establish shared ownership, and a primary-input I/O hook does not imply interception of nested requests. Check callback timing before claiming it can configure authentication. Compare the pinned native source/build with current documentation for credential forwarding, challenge algorithms, cookie scope, TLS verification and proxy behavior. Include fresh/concurrent credentials, model-selected destinations, constructor/debug/tool-error exposure and abort during opening. Keep application-managed auth escape hatches explicit without inventing a session-wide request hook or a second transport runtime.

For component documentation, inventory configuration, source modes, invocation methods and result fields separately from example controls. Verify accepted model/format types for each operation, conditional requiredness and invocation-only settings. Preserve native descriptions with pinned sources and visible local adaptations; prefer exact reuse over unnecessary paraphrases, and check it against the installed contract rather than importing entire SDK parameter tables. Check the actual generated factory and used-property metadata, while keeping teaching restrictions out of API applicability: an approval example is not the entire resume contract, and direct streamed-text examples do not exclude prepared streams. Verify source/Loads transitions and one canonical property explanation with references from other sections. Planned APIs must retain their status and must not be type-checked against fabricated implementations. Read the explanations and examples as a person would; machine-readable exports supplement readable documentation and do not establish its quality. Check exported content and provenance independently of the UI.

For generated reference inventories, compare exact factory sets instead of minimum counts, and keep catalog-family navigation separate from native configuration alternatives. Trace ownership through redeclared SDK types and check multi-operation descriptions against both native paths. Mutation-check misspelled shape/group/choice references and unused local amendments. Freshness must detect a changed public contract while accepting unrelated local comments or line shifts; whole-file hashes alone do not establish that distinction. Check public output declarations against returned fields and compile a consumer. Keep mocks independent of user-facing wording, lint the authoring JavaScript, and inspect the cache inventory after regeneration.

For documentation handoffs, execute the modules after a browser-targeted bundle: dynamic imports that work from repository paths can disappear from a bundle. Check selected resource reads and asset placement separately. Compile representative actual nested exports against the declarations, not only code that trusts those declarations. Cross source preparation with planned type overrides and conditional requiredness; cross invocation-method selectors with their result summaries and fields. Reference all supported method settings/results independently of the example's ordinary-call mode.

Trace the lightweight control entry separately from the full reference snapshot. Test rendering with no injected resource reader, canonical source freshness, restored stale selections, unavailable-choice reasons and the effects of switching choices. Compare canonical references with full selections to prove that example-only choices do not hide API changes. Compile the actual catalog against literal identifiers and check the same property record across configuration and related concepts. Review model-facing tool descriptions independently of reader captions, and compare fixed versus parameterized tool tasks with what the host asks. Record exact checkout provenance at publishing time rather than embedding a moving commit in checked-in generated data.

Audit documentation completeness below top-level configuration: follow exported aliases to their native prose, check result/method/nested field descriptions, and retain separate union branches. Prefer the installed SDK's declaration or reference text; label local fallbacks and preserve independent provenance when prose comes from another native location. Check that every extracted detail is reachable, that Config alternatives navigate to the actual factory reference, and that a separate project's file/workspace dependency can import the documented package and resources without runtime dependencies. Do not turn provider-defined dictionaries or implementation types into invented fixed configuration options.

Check downstream declaration emission, not just consumers of Casai declarations: an application must be able to export inferred components without private type names or inaccessible package paths. Pair generic wrapper/`Parameters` probes with direct-call inference and invalid neighbors. Compare every compatibility finding with the installed native runtime before adding a workaround; record genuinely new SDK settings separately from malformed developer calls. Cross conditional undefined and inherited clearing with native property-presence checks, and verify authored schema errors before model dispatch as well as during tool execution. For data exposure, inspect the application/UI tool result as well as `toModelOutput`: model-facing formatting does not remove provider metadata from saved UI history. Run focused mutations against assertions of observable behavior, and distinguish redundant guard removals from missing coverage.

For configuration-mixing reviews, separate TypeScript admission from runtime validation and pair each negative with a valid call differing only in the disputed setting. Retain invalid fields in explicit union annotations: conditional expressions can infer a common supertype that has already erased them. Inspect that inferred type before calling acceptance a factory loophole. JavaScript probes cannot establish a type-checking defect, and external review recommendations must be reconciled with existing user decisions before changing the contract.

For factory-modifier migrations, trace public kind names and reusable Config shape indexing separately from internal operation selection. Test the flag paired with native settings, early callback inference, annotated config consumers and emitted component declarations. Exercise actual calls after any proposed narrowing: a nested configuration discriminant need not narrow its enclosing callable. Keep component-specific native methods in the public-surface inventory rather than assuming the ordinary-call default controls every entry point.

When moving public selectors into internal metadata, test ordinary object spreads, intermediate Config fragments and independently loaded package copies. Compile exports of the inferred fragments themselves, not only completed components. Compare a union of actual factory return objects with a manually annotated union: nested generic inference can retain only the first provider. Recheck schema-driven callbacks after copying `.config`, both optional-property modes and the SDK request before unknown fields are discarded. Keep parent shape checks when changing where parent inference occurs, and update mutations at the new validation owner.

Make selector examples and inheritance assertions distinguish the selected mode from the component default and its explicit replacement. Check removed-setting diagnostics at constructors, named calls, native methods and continuation, while retaining same-named application data. Inspect symbol-key declarations structurally in reference generators; compiler-internal escaped names are not a stable public contract.

Check source selectors against every native main-input field, with empty children, inherited values and explicit replacements of copied metadata. Keep field roles paired with the compatible owner: a source on one component may be a native non-source setting on another. Test public config annotations as actual factory arguments, preserving both the authored default and a fragment's selected loaded mode. For a loader negative, retain the definitely supplied source field so a missing-source error cannot mask the loader check. In source unions, successful or source-free branches must not hide invalid branches; use explicit union annotations when a conditional expression would erase the disputed field. Reuse the component-owned source contracts and measure annotation helpers separately from factory inference shapes.

For native licensing reviews, inspect the actual prebuild workflow, native link files and included artifacts rather than npm's wrapper-license field. Distinguish compiled GPL/nonfree enablement from runtime codec selection, and static libraries inside a dynamically loaded addon from actual shared-library replacement. Compare optional installation/internal use with redistribution of addons, installers and images. Record exact build provenance and the applicable notice/source/relink requirements; a skipped CLI, optional peer or native configuration string alone is not a complete compliance argument. Preserve independent delivery when an acceptable native build is still unverified. If applications can choose builds, verify the default and explicit choice against actual artifacts without confusing a policy selector with relicensing. Compare alternative wrappers' transitive codec backends. Before replacing a library with a subprocess, check option scope, automatic stream selection, metadata timing, single acquisition, process/stream ownership and credential exposure; reassess unnecessary contract promises before adding compatibility machinery. Keep installation choice and release artifact certification separate from runtime media configuration; do not infer a runtime licensing selector from a requirement to support alternative builds.

For optional media integrations, test installed and bundled consumers with the dependency absent, and inspect the actual native package footprint/platforms. Execute both ESM and CommonJS Node bundles; successful emission does not prove runtime fallback. Distinguish top-level package absence from missing installed entries, transitive dependencies and initialization failures. Trace resource acquisition before dispatch: a stream's pull callback can run before a reader exists. Compare in-band error events, native finish/output requirements and rejected result promises separately before defining a collector. Check binary/container assumptions against specifications, including chunk alignment and zero/unknown lengths. Reuse existing package/coverage fixtures and separate mock contract evidence from real codec/provider evidence; do not block an independent factory migration on optional media deployment work.

Compile installed consumers under every published source condition as well as ordinary declarations, with optional peers absent and repository-only ambient shims unavailable. A private build declaration does not accompany published TypeScript source, and a runtime resolution check does not test that compiler boundary. For lazy media inputs, inventory which facts are known before reading: fixed metadata about actual conversion cannot depend on an unopened encoded header. Separate selecting a processing pipeline from discovering its work, and preserve no-read controls alongside finite-buffer positives.

A failed integration technique is not automatically a product decision for the user. Prototype a simpler supported loader/type boundary before escalating optional-dependency feasibility. When inspection is necessary for a requested result, challenge an artificial no-read contract and account for lookahead, cancellation and pre-handoff ownership. Distinguish lost convenience from lost capability, and verify the same model supports the complete operation before claiming that removing a streaming modifier preserves every call.

Separate public result delivery from native transport when complete wrappers must support streaming-only models. A required `doGenerate` member can still reject an unsupported operation, so test complete-only, stream-only and dual-capability implementations and narrow capability failures independently of ordinary execution errors. Trace input/format requiredness, final result adaptation and tool serialization across that selection; do not make users opt into a public live result just to execute a model that streams internally.

Select a compatible request shape before checking capabilities: raw audio plus a format is not an encoded file, and two native operations can use the same setting name with different types. Count SDK preparation/download/telemetry effects separately from model generation before treating an unsupported-feature error as pre-execution evidence. Preserve native model resolution/version adapters and native retries; prove any cross-operation transition without speculative execution or replay.

For completed stream adapters, trace every emitted fact needed by ordinary and tool consumers, including audio rate and native usage. Compare homogeneous audio with format-changing and metadata-only chunks. Test an error after native finish: already-resolved final promises and an owned output drain can have different outcomes. Keep the smallest family-local result adaptation and avoid a second operation registry or shared completion framework without a demonstrated need. Follow factory renaming into generated API-reference aliases and result metadata as well as example renderers; experimental status follows the native operation, not merely the public delivery toggle.

When evaluating streaming tools, distinguish an SDK's preliminary tool-result events, a component's live ordinary result, and an adapter that collects one completed tool value. Reassess whether the last adapter justifies special modifier/configuration rules before preserving it. A removed capability must be retired through Config flags/inheritance, descriptor projections, guide claims, matrix visibility/restored selections and future-phase requirements; it must not accidentally remove native third-party tools or schema-declared stream contracts. Refresh the implementation baseline before prescribing validators or dependency additions that may already have landed.

Also compile optional integrations with the dependency absent. Keep any internal ambient declaration out of published source/declarations, and compile the actual adapter against real package types with that shim excluded. Verify export conditions and direct test-tool dependencies. Match examples to their delivery stage and make simple-versus-native conversion rules agree across plans and guides; do not let a prototype defer an already selected user-visible result shape.

For chunk adapters, compare against whole-input native behavior across aligned groups, every remainder, split samples and odd byte offsets; distinguish odd sample counts from incomplete samples. Test prefetch and reader-lock release at EOF, error and cancellation during reads. Separate a missing optional package from an installed package's load/decode failure when fallback is supported. Do not infer provider segmentation guarantees from one native finish event or claim actual truncation without provider evidence.

Vary the presence of whole configuration containers independently from their entries. A missing `tools` or `toolsContext` map does not guarantee its helpers or bindings; when inherited, an absent child map also must not invent own undefined entries that overwrite a parent. Trace presence through contextual callback inference, final admission, helper defaults and the shared map merger. Pair conditional values, conditional spreads and optional annotations with explicit entry-level undefined controls. For configuration unions, compare required-source omission on shorthand and named calls: one configured branch must not make the source optional for every branch.

Prove helper precision as well as optionality in inference probes. An assertion that a helper may be undefined can also pass for `any` or an open context fallback. Use schema-backed contexts, exact helper return types, invalid-field negatives and definite-helper/native-hook positives on every inference owner. Check the broad semantic consumer suite before accepting a compiler-cost optimization; inexpensive focused workloads can miss provisional-type timing failures.

Compare native registry annotations as well as inferred tools under both optional-property modes. An SDK's `ToolSet` can admit variants that its default `Tool` generic does not. Use native-accepted literals and annotations as controls, then trace exposed tools, context-name projection and invocation replacements. Preserve admitted native types without attempting to recover information erased by the SDK's inference helpers; distinguish SDK factory limitations from restrictions added by Casai.

Vary an application object's prototype independently from its own fields when reviewing argument roles. Compare shorthand, named calls, replacement sources and explicit structured-source/context pairs with native parsing; retain binary/media and format-slot controls. In history scans, reuse call and approval IDs after earlier results inside the same turn, not only across turn boundaries, and ensure resetting settlement does not revive old requests. Audit verification reachability too: retired-property guards can disable assertions, distinct matrix labels can execute identical paths, and unmarked current-guide examples can escape a future-guide checker. Inspect local assertions in opt-in files without requiring paid execution. Capture observer values and assert after completion when native handling can swallow callback failures. Mutation runners must reject unmatched filters, absent test selections and ambiguous replacement sites; run their full inventory after shared refactors.

For ownership reviews, trace type computation as well as runtime functions: field-specific result inference and tool projections belong with their component. Check shared helpers for copied existing contracts and sibling imports that hide common ownership. Name shared modules by responsibility, and verify that removed source files do not survive as stale generated package contents.

After unifying callable assembly, check helper exports and legacy API aliases across runtime, declarations, guides and package consumers. Keep native SDK descriptor discriminants distinct from removable ordinary-component labels. Mutate shared source resolution, descriptor settings and output collection independently: a common pipeline must retain each owner's real semantics.

Check whether standalone setup is simply a merge into an empty parent before maintaining a separate processor. Trace ownership before copying a freshly assembled configuration again. When deleting a path, consolidate its diagnostics and fault-injection cases around the surviving implementation; retain public-entry checks for standalone and inherited snapshots.

Audit inventories against all public callable exports, including components implemented in earlier phases. A shared name such as `Component` or `ComponentFactory` must cover that whole surface. When consolidating definitions, trace them into actual construction and configuration consumers; adding unused rows is not unification. Compare the same forwarding calls across older and newer components, including positional and named undefined source overrides in runtime and emitted declarations under both optional-property modes. Keep component-specific inference contracts where they protect callback typing, and measure the compiler cost of a larger registry.

Audit downstream callback selectors as well as the component registry: a guard still keyed to `execute | prompt` can silently omit other component-owned preparers. Cross `.run()` tool-context replacement with helper calls that rely on bound public defaults, keeping valid replacements and older-component controls. For source-mode unions, include inline/loaded Template and Script configurations; branch-specific loader requirements matter even when both modes accept identical source strings.

Audit supplementary methods independently of the common callable/run machinery. A `toolsContext` shape alone does not establish that a replacement preserves a Casai tool's implementation dependencies or configured public defaults. Compare per-call overrides with explicit binding and the common run checks, including private dependencies without a tool-context schema. Reuse the applicable binding checks, while keeping tool-only execution independent of the owner's instruction/source payload.

Cross the first asynchronous barrier with reuse of a caller-owned payload object: replace a top-level field immediately after starting a call, then compare ordinary components, ordinary calls on tool components, prepared tools and the native parser/Agent. Repeat with cached metadata; awaiting an already-resolved promise still yields. Capture application input through the common preparation path before unrelated schema-name discovery. Do not infer a need for deep copying from an ordering bug or extend the guarantee to mutation of nested borrowed resources.

Check context extraction and supplied-key inference independently of allowed positional tuples. Binary media can occupy an unambiguous secondary slot but still be mistaken for context by structural object types, or for source by the runtime parser. Compare omitted source/context slots, explicit placeholders and named calls while inspecting the actual native request. Include unions of binary representations and inline replacement preparers: key capture can reject a valid media union, while a broad first-argument union can lose callback inference even when an annotated preparer succeeds.

Keep parsed application input distinct from execution context through downstream adapters. Cross a transform that removes a declared main field with an injected helper of the same name and a configured source fallback. Declared-name metadata alone does not establish the provenance of a property after helper assembly. Compare descriptor, injected and native ToolLoopAgent execution, then remove the transform or matching helper independently to establish the cause.

Revisit guard-removal tests after changing data provenance. Once an adapter reads parsed input instead of assembled context, a private same-named binding no longer exercises its declaration guard. Test a schema transform that synthesizes an undeclared output field as well as one that removes a declared field; confirm which contract each remaining guard protects.

Use exported configuration types as variable annotations and pass those variables to the corresponding factories; assigning an object to a shape or using `satisfies` does not test this consumer. Distinguish ordinary annotations from internal shapes that permit tool mode. Cross inherited source/callback clearing with both optional-property modes, preserving the difference between configuration clearing and call-time omission. Compare native invocation types separately: Casai configuration merging may intentionally admit values that are normalized before SDK dispatch.

For positional result inference, replace documents with a different element type while explicitly omitting source/context slots. An undefined placeholder in another slot must not make a definite document replacement optional. Compare shorthand and named result types, retain genuinely optional replacements as union controls, and inspect the native result as well as call acceptance. Include forwarded tuples with optional slots and values that can occupy different roles, such as a query-or-documents union; result types must retain the configured fallback only on branches that actually omit replacement documents.

Compare copied input shapes with the native owner for readonly arrays and unions of resource representations, including valid inline preparer inference after widening resource admission. Derive result-dependent inputs only after pairing configuration and call alternatives; inspect descriptor output, conversion callbacks and injected helpers as well as ordinary returns. Cross an optional secondary argument in the first available shorthand slot with a configured preparer: a definite override can hide an incorrect source classification because it never consults the fallback result type. Use the owner's source contract before adding another positional classifier.

Compile and execute promoted mock documentation examples. Embedded Cascada field access is invisible to TypeScript, so a helper/result rename can leave a compiling example that fails at runtime. Keep current-guide API claims separate from deliberately future guide features, and test the actual Markdown block when a copied fixture could conceal drift.

Cross an empty child configuration with missing required settings, incompatible inherited settings and schema/preparer mismatches; compare a nonempty child so inference-deferral sentinels cannot silently bypass final validation. Move the same native callback and schema-driven preparer between direct construction and reusable Config, checking both acceptance and inferred parameters. Compare generic callback data such as runtimeContext with the native SDK, not just its erased Parameters type.

For owner-neutral fragments, replace an incompatible annotated callback with an inline callback as the child's only property. Check completion and diagnostics as well as acceptance: validating before contextual inference can erase the override or report only `never`. Cross definite and optional callback/runtime-context overrides with inherited values in both optional-property modes. Keep property presence separate from its inferred value where callbacks depend on it; optional replacement must retain the parent's possible contract.

Cross inferred no-schema callbacks with changed private bindings, comparing retained and replaced implementations, explicit parameter annotations and schema-backed controls. An open index signature can hide named bindings from a key-selection guard, while intersecting old and new binding types can make execution context impossible and validation vacuous. Test reconstructing bindings from resolved runtime facts before adding another guard. Also construct components from unions of different valid source modes: a replacement must be valid for every possible mode, while shared safe calls must remain usable without narrowing the configuration first. Audit callback keys against each native owner's complete supported surface, including aliases, rather than borrowing a language-model callback list. For plain tools, compare parsed input with the native function's required fields after optional values, root transforms and configured fallbacks; add no duplicate SDK runtime validation. Check that a definite child can replace an incompatible parent field before judging the final configuration.

When distributing callable types over configuration alternatives, retain same-mode unions as positive controls: unions of generic call signatures can reject safe replacements even when their argument types agree. Intersect invocation data contracts instead, retaining alternative call forms inside each mode. Structural intersections alone can admit arrays, functions or native media through a context slot; check the actual argument roles against each original contract. Preserve mode/configuration pairing in required settings, input and result inference, include the default for an optional mode, and check explicitly annotated configurations for control-flow narrowing. Continuation and explicit modifier overrides intentionally bypass the stored source mode. Keep positive annotation fixtures valid; put deliberately invalid callback properties in separate negative fixtures so they do not obscure narrowing. Compare older factories before fixing a shared-source issue only in new components. A fragment may defer private dependency compatibility while still checking output and known helper contracts; moving a final-context invariant earlier must not accidentally make fragments complete. For plain tool inputs, trace declaration-based selection as well as parsed types: an empty Zod object can expose a `never` index signature, and a transform can create an output field that was never declared as public input. Keep image-only tools as a positive control when checking required source fields.

When changing bundle ownership, track field precedence through native dispatch and result inference, including optional override unions, query-only replacements and native empty-array semantics. Distinguish configured fallbacks from explicit invocation overrides. Move validation tests to the selected owner when a reusable-fragment contract changes, rather than retaining component-kind guessing to satisfy historical tests. A runtime-pipeline unification must preserve SDK descriptor type, provider-option ownership and output-stream collection. Classify failure-timing differences separately: supported callback scheduling can be load-bearing, while synchronous throws versus promise rejections for malformed calls may be historical accident. Identify any contract change explicitly; do not preserve separate pipelines solely to retain that timing, or weaken valid-call assertions to force unification.

Evaluate simplification experiments separately against the current working implementation, retaining useful smaller reductions when a broader rewrite fails. Trace duplicate representations through their consumers: an invocation-local settings object may own the effective rendered source without another input overlay, while authored configuration, supplied fields and trusted context retain distinct roles. Callable unification must preserve interface-typed payloads, configured defaults beside contextual callbacks, whole argument unions and reflected return types. Cross interface payloads with private/extra keys after string and complete-object sources; a record index signature is not an application-context requirement. Check overload order in editor diagnostics as well as acceptance, and measure component growth separately from import cost. Expanding every positional tuple into an overload can multiply work without improving inference.

During an SDK upgrade, rerun native-only canaries before interpreting failures as wrapper regressions. Inspect new prompt and tool-call checks, preserve native failure behavior, and update affected recipes. Cross authored source, public context defaults and private same-named bindings on ordinary, bound and injected paths; configuration fields must never become implicit payload defaults. Compile both optional-property modes with native model interfaces as well as runtime mocks: SDK mock declarations can themselves differ from the native interface under exact optional checking. Measure large completion unions at generic intersections and preserve bidirectional native assignability when simplifying them.

For prepared sources, cross configured complete bundles with invocation preparers that return only text, and the reverse. Required secondary inputs and field overrides must follow the effective source. When sharing positional signatures, an omitted source must not acquire secondary arguments that are valid only for a replacement source. Optional replacements must retain both supplied and configured result types. Check descriptor callback output inference separately from the returned descriptor's execution type. Preserve established keyword/history exceptions when adding structured sources; named calls provide an explicit source boundary.

Trace mode/configuration pairing through result consumers too: an ordinary scalar result and its tool projection must both stay scalar when every possible branch produces one. Distribution in a downstream conditional can silently lose the original mode union even after call acceptance is correct. Use positive result assertions alongside rejection tests, and mutate that pairing independently.

Include producers whose return type mixes complete and incomplete branches: one complete branch is not a guarantee. Test complete replacement producers separately from configured ones on shorthand, named and tool paths. Cross omitted source/context slots with object-shaped and string secondary arguments, observing the actual SDK request. A tuple accepted as format, voice or language must not be consumed as context or source; require placeholders for genuine ambiguity instead of guessing from application field names.

Compare explicit literal modifiers with the unmodified factory when they select the same source mode; preparation-table headings and guide summaries must not accidentally narrow native literal inputs. When consolidating overlapping contracts, put precedence in one authoritative table and trace every removed rule to that table or its owning section. Check configuration inheritance, invocation overrides and complete producer bundles separately, and retain user-guide examples and implementation acceptance cases without duplicating decision history.

For SDK-ownership reviews, include linked lifecycle guides as active contracts. A stale failure promise can reintroduce removed machinery even when the main plan delegates correctly. Compare cancellation signaling, rejection of a Casai-owned wait and native result resolution separately. Recheck retained-helper rationales against actual public exports and direct dependencies; justify a local adapter by the behavior it supplies, not an obsolete packaging constraint.

For shorthand reviews, inventory every component and source mode before choosing a uniform signature. Identify the most common operation parameters separately from fixed result contracts and execution/trusted-context controls; compare the current native parameter types and defaults. Cross optional positional slots with inherited defaults, required context and forwarding wrappers that pass undefined. Source-shaped application data must remain valid context. Pair each shorthand with its named equivalent and verify the same preparation, parsing and native dispatch; avoid property-name guessing and a second argument-processing pipeline. Distinguish individual-field defaults from complete native bundle replacement. Cross text-only and image/mask updates with inherited media, clearing, preparer-owned bundles and actual model tool execution; configured media must not leak into model argument metadata. Check coupled defaults such as image/mask together, and distinguish an absent native property from an own undefined value. Follow empty collections through a real provider adapter: an empty edit list can choose a different endpoint from absent media. Inventory new SDK operation exports and provider implementations separately, and trace the SDK browser request payload into the server route rather than testing only the final native call. Distinguish a deliberately configured one-shot resource from a hidden mutable current input; consuming opaque configured state does not itself reassign configuration. For a reuse guard, compare native drained-input behavior and specify the handoff boundary, failure ownership, registry scope and outside-consumption limits. Do not conflate a reusable native result getter with one captured stream view. When newer SDK semantics are required, make the dependency floor and fresh-install gate explicit rather than relying on a compatible range to install the latest release.

Cross inputs with alternate native spellings through parent/child configuration and invocation overrides: an invocation-level one-of rule does not resolve both names retained by ordinary shallow inheritance. Check that each source mode leaves an actual configuration location for its advertised secondary defaults. Review configuration inheritance separately from invocation patch rules; Config fragments can flatten layers before a final factory sees them. Reuse ordinary merging unless an additional dependency rule is explicitly selected, and keep runtime and emitted configuration types aligned. A complete producer bundle is not a substitute when accepting that bundle forbids the promised independent overrides. Trace tool formatters through each consumer protocol too; language-generation conversion does not imply realtime function-output conversion. Cross successful void results with HTTP serialization and native callback sentinels: completion returning undefined can mean no automatic submission to the next consumer.

Locate authored source preparation and schema-owned application/model arguments on each entry path before assigning argument roles. Model tool arguments are named; a source override remains distinct from a same-named context/tool field. A schema transforms only the value at its own boundary. Inventory promised raw forms rather than assuming arbitrary data-to-prompt conversion is part of shorthand. Trace configured public defaults into the original parser and advertised requiredness separately from filtering default annotations; an omitted field can still fail even after private metadata is hidden. For structured templates, distinguish native output placement from independent rendering without inventing a public ordering feature. After a browser callback failure, verify actual tool-result submission rather than treating an error observer as completion.

Before treating those interactions as API defects, establish that the counterexample's input form is actually promised. Named model-tool arguments are not positional shorthand, and application-data-to-prompt composition belongs in an explicit preparer. A deliberately invalid proxy can expose a necessary adapter boundary without proving the selected component API invalid. Do not turn internal rendering of native text fields into an unsolicited public slot/stream-ordering feature. Retract unsupported conclusions explicitly and preserve valid native observations as implementation acceptance evidence.

When adapting stop conditions for tool completion, observe the SDK's actual decision rather than inferring exhaustion from step counts or evaluating the predicate again. Pair schema-valid output after a cutoff with natural completion exactly at the limit, and compare ordinary result consumers with descriptor/injected callers. Check absent, hook-cleared, replaced, custom and array conditions. Preserve synchronous throw timing: an async wrapper can turn a synchronous predicate failure into a rejection and allow later array predicates to run when native evaluation would not. Pin that distinction and the native default/eligibility rules with SDK-only controls.

For nested-agent completion, compare decisions transported in step-hook requests with the native response log: request edits need not appear in that log. Apply any supplementary evidence in execution order, against the particular call definition that emitted the request. Cross early/stale decisions, same-ID redefinitions, deferred results, concurrent invocations and hooks installed by `prepareCall`. Verify failure propagation in generation before adding completed-step or failure tracking; streaming's ability to expose earlier steps after a later failure does not imply generation returns a partial result. Preserve native scheduling: a hook cannot approve a next step that the SDK never starts.

Before adding another guard to an integration, reassess the accumulated contract and identify its owner. Separate Casai argument/message construction, native SDK execution and generation-only nested-tool completion. A native failure or inconvenient error timing does not by itself justify a wrapper workaround. The [2026-10-30 resume scope revision](phase4-review.md#sdk-backed-resume-scope-revision-2026-10-30) removes whole-history preflight: compare native behavior and document its limits instead of preserving superseded rejection rules. Test pure message transforms independently, then compare shared dispatch with native calls; reuse existing SDK canaries rather than duplicating their full matrices. When removing an input-presence guard, distinguish absence from a present invalid value, exercise hook-filled and empty final requests, and preserve the public type contract unless its change is intended. A proposed simplification that passes all but an unusual case still changes the contract: identify the lost guarantee before deleting or changing that assertion. Test the remaining boundary, not an independent protocol implementation.

For output simplification, compare native parsed output and live text on the same execution, with pending and settled controls. Schema-valid output does not prove workflow completion. Keep the completion check at the generation-only tool adapter, and test ordinary native output separately. Removed public `value`, final-answer buffering and stream error-cause recovery must not reappear as new wrappers. Test incompatible modifier inheritance in both directions and migrate every stream consumer to its intended native property.

After removing a result convenience, audit verification rows as well as API prose for obsolete delivery and buffering requirements. Inspect embedded Cascada source in opt-in tests too: compiler checks cannot detect a removed property inside a string. Extract that consumer and replay it with a mock, pairing the original failure with the migrated access; local composition contracts should not require a paid model call. Trace callback output separately from result getters: the SDK can omit an observer's parsed output when no specification was supplied while the result still has default text. A legacy negative can pass for an unrelated retired setting; replace that setting with a valid native Output before testing the intended guard. Inference mutations need assertions that reject any widening, not only assignments that any also satisfies. For overlapping native argument guards, target closed/private-input validation independently of required-property syntax.

## Establish the surface

Cross valid output-mode transitions with explicit removal of inherited mode-specific fields; rejecting removal of a still-required schema does not establish that clearing an obsolete schema or enum works. Check optional schema removal on Script as well as Function under both consumer optional-property modes. For function prompts, pair each whole-configuration branch's parser with its own callback and use raw input accepted by every branch; compare ordinary Function, inherited prompt configurations and direct child unions separately. A branchwise compatibility fix need not solve independent inference-slot rejection, and a successful union member must never erase a failing one.

When allowing mode-specific settings to be cleared, test annotated streaming configs whose unsupported enum slot is explicitly undefined, and carry cleared metadata into a later mode that supports it again. Keep constructor-only clearing fields out of run-setting completion. Derive required fields per complete configuration alternative before collecting missing keys; selecting the keys of a combined union can hide one branch's required schema.

After consolidating validation, reassess both diagnostic and guard duplication. Intersecting two different literal error messages can reduce a useful diagnostic to `never`. A surviving guard-removal mutation can indicate overlapping enforcement rather than missing rejection: test removal against the complete consumers, then keep one owner and mutate that shared boundary without discarding the original invalid cases.

For inference-constraint simplification, distinguish the configuration value contract from the provisional shape used to infer it. Trace every child and parent consumer before folding wrappers into an existing type. Centralize repeated compositions while preserving `Partial` placement, intersections, overload order and post-inference parent checks. Probe removal of each layer against valid calls and invalid neighbors; compare contextual editor types, emitted consumers and compiler instantiations on the same workload before calling the result equivalent.

When replacing a type-only inference marker with structural detection, test empty arguments, values annotated only as `object`, optional implementations, inherited dependencies and nested SDK callback arrays. A candidate can preserve callback inference while silently skipping real validation. Test conditional rest-parameter and defaulted-generic alternatives against valid-call arity as well as diagnostic wording, and do not count fewer instantiations as an improvement when rejection checks have disappeared.

Reassess older generic parameters after introducing independent callback/schema inference. A parameter used only to specialize a family constraint may duplicate a newer inference source; compare replacing it with its broad contract while retaining exact validation of the actual configuration. Check standalone tool selectors, literal enum callbacks and malformed schema values as well as inherited callbacks. A passing barrier-removal experiment does not establish a simplification if it substantially increases compiler work.

Check literal preservation and mutability before removing an enum element parameter: a callback array parameter can preserve string checking while widening every literal, and a const parameter can change a mutable array into a readonly tuple. When replacing an inferred final-config parameter with a derived merge, explicitly preserve its constraint on the actual merged values, including raw-parent schemas. Compare ambiguous output fields with complete configuration alternatives before replacing conditional return types with a native result alias. Reassess inherited-setting checks and return-inference barriers in the new structure rather than copying them from another factory.

When extending a factory simplification, compare whole families before extracting shared types: prompt/source capabilities, synchronous versus prepared streaming, native partial/element results and callable versus descriptor inputs remain distinct. Keep factory signatures local; share their repeated configuration, callback and validation rules. A required callback's presence belongs with its shared compatibility check. Test return annotations as well as arguments: they can infer a nonexistent parent or erase callback-inferred fields. Locate inference barriers using correlated schema/default alternatives and private registry bindings, not just standalone annotated calls; a barrier on a nested config or parent can alter downstream conditional-type behavior even when direct binding still rejects the invalid case. Explicitly erased runtime matrices do not replace uncast compiler consumers.

Cross explicit schema removal with a changed output mode under exact-optional emitted consumers. An overly narrow inference shape can discard the actual child and retain a parent's schema before final validation sees it; inspect the inferred `.config`, not just the diagnostic. Keep ordinary optional schema fields separate from required tool fields in final shapes. Exact-optional mutation fixtures must emit fresh declarations from their own source snapshot rather than relying on a previous root build.

Name helpers by their actual role: inferred definitions, callback contracts and validation of incomplete fragments are different concepts. Before adding an alias for readability, look for an existing composition that other factories reconstruct, and share it without moving inference barriers or changing union distribution.

When reorganizing type ownership, trace consumers before choosing module boundaries. Keep schema inspection independent of component policy, distinguish caller input from parsed execution context, and place results, configuration projections and reusable utilities with their existing owners. Preserve required type recursion without adding runtime imports or a forwarding barrel. Move mutation targets and their type dependencies together: a missing import must never count as evidence that a guard mutation was detected. Compare emitted runtime and public source/declaration/editor behavior after the move.

Inventory the whole types directory, not only the file being split. Check native-derived aliases, type-only re-exports, runtime constants/validators and exports referenced only by compiler fixtures. A single external consumer does not imply moving a type when it belongs to a cohesive family with shared private helpers; move implementation-only views and final factory signatures to their implementations. Keep an explicit owner map and distinguish general primitives from domain policy. Preserve public export names while eliminating internal forwarding aliases.

Audit root runtime exports and type-only exports separately: `keyof typeof import(...)` does not inventory type aliases. Justify proposed type exports with reusable application consumers, including raw-versus-parsed schemas, configured dependencies, mixed loaders and tool maps with removal entries. Check source and emitted declarations in both supported optional-property modes. Distinguish declaration reachability needed for inference from a convenient root import; compare native aliases' defaults as well as their fields before recommending removal. A missing module or unrelated consumer error must not count as evidence for an export decision.

For factory performance, measure imports alone and multiple sizes of the same component workload against the immediately preceding source, not only an old aggregate budget. Report incremental instantiations separately from total imports, compiler time and memory; a cold aggregate reduction can hide growth per component. Test constraint reductions against native option types, public completion, both optional modes and guard mutations. Keep unresolved increases explicit instead of calling a permissive ceiling a fix. For output-mode checks, distinguish reusable fragments from completed components, inherited values from explicit clearing, and SDK validator rules from values its public entry point silently omits before validation; assert rejection before preparer/provider effects.

Keep factory-specific signatures beside their implementation; shared configuration types belong in the types layer. When simplifying a factory argument, review its complete admission, inference and validation contract rather than hiding a broad capture constraint behind an alias. Share repeated signature definitions where call forms differ only by parent presence, while retaining their arity, parent validation and processed-versus-inherited result types. Mutate the capture constraint itself: a supported-family constraint can let provisional inference conceal invalid supplied keys.

Before attributing a failed constraint substitution to its placement, vary object admission independently from the all-optional family shape and provisional validation. Test `object & Shape` as well as `Shape`; an optional structural shape alone need not produce the intended inference. Separately move schema/context inference sources and already-inferred parent checks, since those operations can lose callback inference or exceed compiler depth even when moving the child family constraint succeeds.

For an already-inferred parent, test `NoInfer` around the family bound in the type-parameter constraint before concluding that the check must stay on the argument. A broad parent bound can otherwise drive recursive inference through the child's generic settings. Reduce depth failures to their actual triggering expression: inheriting a callback-bearing loader is different from inheriting an empty loader configuration. Keep new diagnostic probes separate from the established contract until the unmodified baseline confirms their expected types.

When collapsing overloads into one factory type, preserve the distinction between an absent parent and a supplied empty parent. Test empty and one-element argument tuples, plus a tuple union whose parent might be absent: accepting that union while returning guaranteed inherited fields is unsound. Infer presence from the actual parent type only when the rest tuple and result use the same condition. Reassess existing mutations after changing the inference structure; an old compiler-depth failure may disappear while the barrier still reduces compiler work.

Also test contextual return annotations and nested factory calls when a type parameter represents argument presence. An expected `ConfigProvider` result must not infer a parent that was never supplied. Block inference from the returned parent contribution while retaining ordinary argument inference, and pair valid annotated results with checks that expected types cannot invent inherited fields.

For historical signature comparisons, distinguish replaying old overloads against current dependencies from running the complete historical environment. Compare explicit type-argument order and arity as well as inferred calls. Trace the actual merge type and runtime policy, including retained map fields, concatenated messages, optional children and union alternatives. Check empty children and manually supplied parent providers; structural parent admission, exact merged-family compatibility and finished-component readiness are distinct guarantees. Mutate merged validation independently of the parent-property check.

For inline-type cleanup, inventory runtime annotations and supporting typedefs as well as factory constraints. A local alias can reveal a shared domain contract that other modules still spell out; keep prompt values distinct from prompt callbacks, and configured tool entries distinct from executable registries. Repetition alone does not justify naming simple primitive constraints.

Inventory exports, factory modifiers, callable forms, inherited configuration, `.run()`, tool adapters, result getters, callbacks, and downstream Script/Template consumers. Include descriptor copies, symbol-keyed bindings and idle stream views after a task boundary. Check mixed positional/keyword calls for rejection rather than silent argument loss. Separate implemented requirements from explicitly deferred work and accepted native limitations. Reconcile current status and links with existing files; date historical evidence instead of labelling it current. Check runtime behavior and public types separately. Inspect assertions in LLM-backed test files too: local configuration, loader, and error behavior belongs in mock-only coverage so validating it never requires a paid model call.

For each boundary, record its inputs, owner, output, failure behavior, and authoritative evidence. Follow a value through configuration, argument resolution, preparation, SDK execution, augmentation, consumption, tool conversion, and a subsequent conversation turn. Include empty, missing, optional, union-valued, transformed, and asynchronous inputs.

For each inferred guarantee, test the branch where its enforcing value or parameter is absent. Distinguish a preliminary shape used for inference from the final proof of completeness: accepting `{}` against the former does not justify a zero-argument call, and an optional-parameter intersection cannot reject an omitted parameter. Cross incomplete union-valued defaults with shorthand, explicit empty arguments and `.run()` on the same component. For conditional schemas, separately execute present and absent branches and check both callback input and returned output types through their downstream consumers; an optional declared contract and a required property holding `Schema | undefined` are different cases.

For a conditional input schema, also vary a configured field declared by its present branch. Removing the schema changes that field from a public default to a private binding. A correction must represent both accepted-call contracts as well as both raw/parsed execution contexts; changing only the body field types is insufficient.

State the guarantee across alternatives before choosing a conditional-type operation. A call must work for every possible argument/configuration state; one complete schema branch must accept each effective input; a result must include every possible parsed outcome. Vary the position of alternatives independently: a field value, whole argument, schema, whole configuration, inherited fragment and registry entry. `{ schema: S | undefined }` does not exercise the same extraction as `{ schema: S } | {}`. Audit `keyof`, non-distributive `Omit`, setting accessors and whole-union predicates at each step. Mix closed and open/catchall branches in one discriminated schema; a global open/closed flag must not weaken a closed branch. Pair each case with valid neighbors and actual downstream operations, and compare suspected restrictions with explicit contract exceptions before reporting them as bugs.

Repeat that audit for settings not used in application/result inference. A branch-only tool registry must retain its required context, and a branch-only inherited callback must still match a replaced schema. Pair a forbidden setting present in one alternative with a valid absent-setting alternative: filtering a union to its valid members and testing for a nonempty result proves only that some configuration is valid. Final factory admission must reject any invalid possible configuration. Compare the same conditional settings with native SDK construction, then exercise the selected branch through callbacks and execution. For streaming failures, inspect error parts as well as completion promises; native partial steps can resolve even when execution emits an error.

When fixing alternative admission, preserve each complete branch before deriving its expected contract. Collect failures with `never` for a successful branch; a distributed `unknown` success can erase other branches' errors. Test positive correlations as well as rejection: tools paired with their context, callbacks paired with their schema, and mode-specific properties paired with object/enum output. Compare new restrictions with the pre-fix implementation before accepting them. A stricter key check must not mistake legitimate branch-specific settings for unknown properties.

Keep mutation evidence specific to its layer. Focused shared-owner mutations can isolate expensive type predicates, but they complement rather than replace exported-factory negatives, valid neighbors, source/declaration compilation and editor checks. Distinguish these from mutations tested through actual public consumers. Timeouts and interrupted checks are incomplete evidence; compare compiler cost on the same workload and avoid treating concurrent wall-clock timings as a regression measurement.

Run memory-heavy compiler, language-service and typed-lint checks sequentially when the workspace is constrained. If lint stalls, isolate its file and rule and compare standalone compiler checks before attributing the cost to the public API. Runtime-only fixtures may explicitly erase types at an annotated `unknown` boundary before asserting a small callable shape; keep those separate from uncast public compiler consumers. A direct double assertion on a generic factory can make assertion lint expand its entire API; isolate the exact rule/expression before changing production types or weakening checks. If lint needs smaller batches, enumerate the same complete file set with unchanged configuration and rules. Record successful batches separately from interrupted monolithic attempts; a resource limit is neither a passing check nor evidence of a production defect.

For asynchronous verification processes, report success only after the full assertion sequence completes. An unresolved promise alone does not keep Node alive; a zero process exit is insufficient if expected completion markers are missing. Keep process cleanup independent from assertion success, drain child output before checking its exit, and verify a forced assertion failure produces a nonzero status. Interrupted language-server sessions are not completed editor checks.

When changing generic inference, compare explicitly conditional properties with optional annotations and conditional spreads. Test the final exported factory, not just its internal signature alias: attaching modifiers with `Object.assign` or an object shorthand can accidentally expose the implementation signature. When moving a generic constraint after inference to avoid compiler-depth limits, retain its rejection of every invalid alternative; checking only the merged result can erase an invalid parent branch. Verify valid callbacks, inherited replacements, unknown-setting rejection, editor completion, emitted declarations and measured compiler cost before accepting an inference refactor.

Use the confirmed parent argument for whole configuration alternatives; an unsupported child spread is not a reason to add another initialization pattern. Separate that factory-inference question from call-argument unions. Cross whole arguments with branch-only catchall values, optional `undefined`, private names and disjoint valid extras. A required-key check can reject a valid union, while a wider signature can infer only its common fields and miss an invalid branch. Test the same calls through unions of required and optional components: tuple capture that fixes an individual call can accidentally admit zero arguments. The user permits requiring narrowing for different component alternatives when it simplifies the implementation; preserve valid calls after narrowing and reject every unsafe combined call. Test two optional components as well as mixed required/optional ones, and retain contextual function-valued input inference.

Also vary the entire invocation-settings envelope: `{ maxOutputTokens: number } | { context: ... }` is different from a present `context` whose value is a union. A common-key test must not skip validation of a context present in only one settings alternative. Retain valid absent-context/defaulted-input neighbors and verify rejection before rendering or model dispatch. Treat compiler inference experiments that weaken component-union calls as failed experiments, not fixes; discuss a supported-call contract change before integration.

Separate a union of components from one component created with a union of complete configurations. Renderer argument tuples must not distribute configurations before deciding whether input may be omitted: an optional branch can otherwise introduce a zero-argument overload that skips the complete-input guard. Check omitted arguments, explicit source, named calls and valid fully configured neighbors across coded and model renderers, including parent configuration alternatives.

Cross provided-key inference with mapped/intersection execution contexts and ordinary indexed interfaces. An uninferred key slot must not turn a supplied object into empty input, and a broad index signature must not erase an explicitly named private field. Pair valid body-to-child forwarding with a named-private-field rejection and a real model forwarding attempt. Keep contextual callback/default cases too: dropping provided-key inference can restore the mapped-input case while rejecting an omitted configured field in a callback literal.

For helper substitution, compare accepted raw calls, configured omissions, private names and completed results separately from SDK descriptor compatibility. Generic signature assignability alone can accept incompatible helpers. If a type-only structural contract is used, test open-to-closed replacement, newly constrained optional extras, mixed unions whose openness changes branches, conditional defaults and selected parsers. Retain compatible widening, new callbacks and ordinary native tools. Mutate each distinct obligation; measure a registry workload as well as ordinary calls. No type-only proof establishes runtime validation or private-data enforcement.

Inventory schema-dependent native properties from the installed SDK, including properties inherited from a shared configuration base. Check contextual inference, explicitly annotated callbacks and inherited callback reuse after a schema change. Compare exported callback aliases against the actual callable SDK request: older aliases can remain exported with different event or return contracts. A callback omitted from a hand-written property selection can evade compatibility checks; successful runtime copying does not prove correct inference. Compare a valid inline callback with its native equivalent, and require each claimed unsafe call to compile without unrelated implicit-any errors or casts.

For a whole-phase review, maintain an evidence ledger rather than treating this document's checklist as completion evidence. Inventory in both directions: requirements to runtime/type consumers, and exports/modifiers/internal consumers back to requirements. Each row must distinguish demonstrated behavior, a specified but unimplemented obligation, an accepted native limitation, and an unresolved design gate. Record the actual assertions and native comparison, not just a test-file name or passing count. Include an explicit second pass from consumers after corrections, with remaining gates visible; do not label that pass clean while important gates remain. See the [Phase 2 ledger](phase2-review.md) for an example.

## Run a change-impact pass

For a phase that changes public behavior, use a finite change ledger before reviewing implementation details. A surface inventory says where to look; it does not establish that each consumer follows the new contract.

1. **List behavior deltas, not just features.** For each change, write an old call, its new outcome, and a valid neighboring call. Include defaults, names, callback arguments, error ownership, result types and consumption. Mark behavior deliberately retained, such as native tools' `contextSchema` and retiring factories' existing call forms.
2. **Find consumers independently of the plan.** Search exports, construction/call sites, inherited fragments, README code blocks, runtime assertions and compiler positives/negatives. Use syntax-aware scans where they help distinguish configuration from native SDK properties. Treat scans as candidate inventories, not proofs of completeness. Assign each hit to a change, an intentional native/legacy example, or a dated counterexample; do not leave unexplained hits or blindly rename matching text.
3. **Record an actionable row.** Each delta needs its owning slice, concrete runtime and type consumers, example/migration action, and evidence status: current baseline, demonstrated candidate, implementation acceptance test, or unresolved decision. A test name or passing count does not close a row. Current-behavior tests change with production; target documentation may change now.
4. **Cross boundaries by risk.** Prioritize new behavior plus inheritance/overrides plus a different consumer. For every validation owner, separately inject input, trusted-context, output and lazy-element failure. Check both Casai and plain native registry entries, SDK and coded callers, and actual downstream error conversion. Success-path equivalence does not imply failure-path equivalence.
5. **Trace confidentiality through failure transport.** A private sentinel must stay absent from normalized next-provider requests and model/UI error text, as well as successful arguments. Assert a next request actually exists when testing continuation. `JSON.stringify(Error)` can omit its message and produce a false negative; inspect the message and the real SDK transport. Native validation before executor entry can stop a run, while the same error inside an outer tool can become model-visible output. Retain native causes for trusted diagnostics without copying private values into Casai-owned public summaries; do not invent a universal error scrubber.
6. **Challenge the evidence.** Pair each negative case with a valid neighbor and independently remove important guards or adapters. Run actual callable source/emitted types and example checks; type algebra and runtime-erased fixtures answer different questions. Compare native behavior before classifying a difference as a defect. For lazy shared preparation, identify every first consumer: metadata, argument validation, approval revalidation and injected invocation can run in different orders. Test failed setup with zero provider requests as well as a successful next request; inspect stream parts and UI chunks even when history/completion promises reject. An error type shared by two paths does not prove that both paths have the same boundary.
7. **Close from consumers back to changes.** After corrections, revisit every ledger row, not just the new failing test. State which gates were checked and which remain assigned to implementation. Begin independent slices once their contract is settled; do not claim whole-phase completion while production acceptance rows remain open. No review can guarantee zero defects, but an unassigned consumer or unchecked boundary must be visible.

Audit the primitives that enforce each invariant across consumers, not only each feature's happy path. For name-indexed maps, enumerate dynamic reads, writes and presence tests in defaults, registries, context selection, binding checks and metadata projection. Compare empty maps and ordinary names with `toString`, `constructor` and `__proto__`, including own `undefined` and valid own overrides. Assignment can invoke an inherited setter; a TypeScript assignability test can count inherited Object members as present even when `keyof` does not. Pair runtime presence with declared-key typing and mutate each correction independently. These are small map operations, not grounds for a general key blacklist or changing native parser behavior. The [dictionary-boundary pass](phase2-review.md#dictionary-boundary-and-whole-surface-pass-2026-10-19) demonstrates why an input-payload prototype test alone misses them.

See the [Phase 2 consumer-first pass](phase2-review.md#consumer-first-review-2026-10-19) for the ledger and failure-owner matrix produced by this method, and the [binding continuation follow-up](phase2-review.md#binding-continuation-and-call-envelope-follow-up-2026-10-19) for the first-consumer and zero-request cases that pass initially missed. Check every recommended fix against its actual authority: an unknown-key settings guard does not prevent a recognized source key from executing, and SDK-owned settings must not silently acquire a Casai whitelist.

## Review a pass

1. Challenge the contract before fixing a mismatch. Prefer the native SDK or Cascada contract when it serves the intended behavior with less machinery. Inspect the installed SDK Agent/tool types and `ToolLoopAgent`, following delegation into the owning execution, schema, approval, and history modules before proposing a parallel Casai mechanism. Read native tests when available and use focused native probes; see the [native SDK reference](plan.md#native-sdk-reference). Compare suspected inherited limitations directly with the native API, including Agent where relevant. Do not add machinery for deliberately invalid or very unlikely developer code unless the correction is simple or the boundary is exploitable by an end user/model.
2. Read every applicable dispatch path. Compare sibling factories and modifiers, but do not require identical envelopes or timing when their native capabilities differ. Exercise installed provider adapters with representative HTTP/SSE fixtures and fake fetch, alongside SDK model mocks. Compare normalized and raw finish reasons, content blocks, provider tools, and refusals; mocks alone cannot establish what an adapter exposes. An invalid fixture leaves that API unverified.
3. Exercise interactions, not only isolated settings: inheritance plus overrides; preparation plus cancellation or caller mutation; retries plus transforms; tool work plus finish reasons; result consumers plus early closure, failures, and repeated access; overall versus final-step finish reasons changed independently by SDK transforms; parsed values plus downstream tool/history use. Inject faults before the first provider stream is returned, inside a returned stream, and during continuation setup, across invocation modes, output kinds, and consumer orders. Compare error identity and causes as well as success/failure; these boundaries can use different native error paths.
4. Check equivalence and ownership properties. One invocation executes once; successful final output matches the same execution's native parsed output; native fields/callbacks remain native, including callback receivers and capture timing; shared configuration and caller arrays remain intact; history follows native message availability and records the same input block that was executed. Mutate borrowed request arrays and top-level settings after entry, including on literal SDK paths rather than only through renderers. Respect the documented consumption contract for custom iterators and object streams.
5. Check exact public inference with the supported consumer compiler (TS7) against source and built declarations, in both optional-property modes. Pair rejected cases with valid neighbors. Include optional settings, unions with branch-only keys, inherited alternatives, custom output kinds, and SDK tool-map consumers. Casts cannot prove a public type contract. If a runtime test batches heterogeneous components whose signatures require narrowing, keep its explicit type erasure local to that matrix and retain concrete, uncast compiler positives and negatives; an uncallable component union can make an expected rejection vacuous.
6. Run `npm run test:coverage` and inspect uncovered branches against the changed runtime paths. Record retained native-precondition guards explicitly; do not add coverage exclusions or contrived invalid calls just to reach 100%. Check declaration-only changes with `test:types`. For important guards or proposed removals, identify a meaningful counterexample and run a targeted mutation. Verify the exact owner changed after refactors; first-match text replacement can target a sibling path. Distinguish equivalent survivors from missing coverage and native behavior. Do not retain redundant implementation branches merely to satisfy a mutation score. Restore mutated files byte-for-byte before normal verification.
7. Trace each finding to a reproducible case, intended contract, user-visible consequence, native comparison, and resolution. Add focused regression coverage for confirmed bugs. Record accepted limitations and unresolved decisions explicitly; do not silently weaken the requirement.

## Improve the next pass

For a focused security pass, construct an attack-path ledger independently of the feature checklist. For each attacker-controlled source, identify the transformations and forwarding hops, the private facts available at each boundary, and the first execution or disclosure sink. Separate binding replacement, mutation, confidentiality and executable-source/control injection. A guard protects a path only if its facts are available before the relevant sink; preparation-time declarations and actual execution-time context are distinct. Cross bare context with unknown declarations and actual private fields, and cross nested input/output failures with next-provider and UI publication. Check sibling/owner isolation as well as replacement. Every important guard needs a counterfactual mutation that reaches its sink, with a valid neighbor; record production-only paths as gates instead of treating fixture coverage as integration evidence.

Assess proposed protective mechanisms against a concrete attack, their enforcement owner, what remains unprotected, compatibility cost, and an independent failure-detecting test. Separate required enforcement from optional hardening and application authorization; more guards are not inherently safer. Curated loops and mutation tests are not evidence of broad generated schema/path coverage. Generated cases need a bounded grammar, reproducible inputs/seeds and an independent oracle, with unsupported cases and accepted authoring limitations labeled separately. Revisit the native ownership contract when changing purity/state assumptions: ordering within one execution may impose stricter identity-sharing rules than merely offering no global lock. A new wrapper or shallow copy does not establish isolation of nested state. Distinguish an independent review of the integrated implementation from another pass over the author's fixture.

Verify whether an upstream restriction is enforced or is a host obligation, and distinguish overlapping executions from sequential reuse. In generated cases, native parsing determines stripped/retained values but an independently declared test partition determines private ownership. Do not derive the expected protected-name set from the helper under test. Context parsing may itself materialize a prototype-named declared field, while application parsing may strip a prototype-shaped extra; neither should be misclassified as a Casai substitution. When a guard-removal mutation survives, check whether another guard still enforces the same path. Test the actual semantic exemption rather than claiming every redundant check is independently necessary.

For native security settings, test the lifecycle they actually govern: provider advertisement, fresh response parsing, local execution, approved-history continuation and trusted coded forwarding can use different registries/policies. A native signature can authenticate public input without binding a tenant, session, implementation or replay identity. Cross valid signed history with changed private context and current denial/removal policy. Follow parsing upstream of a wider executor registry before claiming a bypass. Compare native and adapted behavior, then classify a concrete adapter defect separately from a native limitation or application authorization obligation. During integration, connect every real consumer with these checks in its owning slice; a final independent audit cannot replace enforcement implemented and verified along the way.

Security probes must compile through the intended public APIs where their calls are valid. An unsafe-input cast can exercise runtime rejection, but do not hide an unrelated inference failure behind that cast. Cross output constraints with context-dependent callback inference and registered alternatives; check positive producer inference as well as negative return checks. Generic return checks can run before callback inference, and non-distributive helper inference can destroy correlations between alternative tools. These are type-contract findings, not evidence of a runtime security bypass.

Test partial knowledge separately from complete knowledge and complete opacity. A classifier that cannot describe one branch must not erase security facts already established by another. For each discovery result, distinguish "these names are known" from "all names are known" and check what each consumer actually needs. Cross supported/opaque alternatives in both orders, active/inactive branches, absent optional values, wrappers and actual downstream execution. Input-default partitioning and private-name reservation need different certainty; do not apply an all-or-nothing capability check to both. A characterization test can preserve a flawed assumption, so verify its expected outcome against the invariant rather than treating its existence as evidence. See the [mixed-context-union finding](phase2-review.md#partial-context-knowledge-review-2026-10-20).

For every conditional runtime capability, enumerate all triggers and compare them with factory admission. Default selection, private reservations, executable registries and binding can independently require the same operation; checking only the first trigger in types leaves valid-looking components that cannot run. Include inherited and removed entries, wrappers, opaque alternatives, and metadata-backed valid neighbors. Give each independent trigger its own mutation instead of relying on a broad failing schema test.

Verify that each final factory actually applies shared admission and call guards; the existence of a shared helper or a passing coded-factory test does not establish its use by LLM renderers and tool forms. Pass the same union-valued argument through shorthand, coded run and LLM run, with a forbidden/private key in only one alternative. Distinguish all possible supplied keys from keys common to every alternative, without weakening complete-input checks. Likewise, cross schema alternatives that change delivery: a stream schema or a scalar schema needs separate ordinary-producer and collected-tool result types. Follow those alternatives into injected helpers and descriptor callbacks, and execute an operation the inferred type permits. Concrete-kind and schema-present/absent tests alone do not cover these cases.

Pair branch-only forbidden names with branch-only permitted extras and disjoint catchall keys. Inferring every possible key must not require every key in every alternative. Before relaxing that restriction, check wrong catchall values and explicit undefined in a branch that can be structurally hidden by another alternative. An inferred generic can narrow away supplied value information even when a separate generic retains its key; a partial key map alone does not establish soundness. Keep known-restriction characterization tests distinct from accepted API behavior.

For helper replacement, compare the calls accepted before and after replacement, not the source of an omission guarantee. A schema default can preserve an omission previously supplied by configuration. The reverse replacement can still be invalid because an optional schema accepts explicit `undefined` while a configured required field does not. Cross these directions with selected schemas and keep raw-value, omission, private-name and result obligations separate.

Check registry binding settings separately from replacement SDK descriptors: the former produce raw context, while descriptor executors and hooks consume parsed context. Cross a context transform with both valid and incompatible replacements, and include a tool without a context schema. Use the SDK's inferred descriptor context instead of reconstructing it from a producer-facing settings map.

When a replacement type also permits the original descriptor type, make the valid replacement structurally different while retaining its intended contracts. An identical schema/configuration shape can take that original-descriptor branch and leave the general SDK compatibility check untested. Repeat the check with and without a retained coded preparer.

Distinguish optional positional arguments from optional properties inside their objects. In exact-optional mode, an optional tuple member does not automatically accept explicit `undefined`. Test omission and explicit `undefined` on every supported source/history position, while retaining rejection of missing required input and invalid present object fields. Helper omission guarantees must also account for invalid configured values and fields required by any input-union branch. Compare ordinary native function assignability when a contract wrapper loses otherwise valid discriminator reasoning.

For model/private-data boundaries, distinguish confidentiality, replacement of a binding, and mutation of its object. Test open/catchall input, absent optional private slots, root transforms, nested public objects containing configured data, native refinement after validation, approval continuation, and forwarding through ordinary child calls or `.run()`.
